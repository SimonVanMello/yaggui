# Manual validation of milestone M7 (= V2)

Guide for validating M7 (persistent undo, fixup and autosquash, one file from a stash, first-parent history, preferences import / export, history of a line range, files at a commit, assisted bisect) on **macOS** and **Windows**, plus the fix that gives Git hooks the `PATH` of the login shell (PR #58). Allow about 1 h 30 per OS.

The status of the V2 requirements is in [V1-audit.md](V1-audit.md) §6. Prerequisites and launch are the same as in [M0.md](M0.md) §1–2, and the checklist conventions as in [M1.md](M1.md) §2. M4 ([M4.md](M4.md)) does not have to be validated first: the items below say when they rely on an M4 behavior.

```bash
git pull && pnpm install
pnpm tauri dev                          # dev mode
pnpm tauri build --debug --no-bundle    # binary with the production CSP (use it to validate screens)
YAGGUI_CONFIG_DIR=/an/empty/dir pnpm tauri dev   # isolated session: no existing repositories or preferences
```

The persistent undo and the hook `PATH` must be validated with a **built app**, quit and started again for real: `pnpm tauri build --debug --no-bundle`, then on macOS `pnpm tauri build --debug` and open the `.app` from the Finder or the Dock (§2 "Git hooks and `PATH`"). Under `pnpm tauri dev`, yaggui inherits the terminal's `PATH`, which hides the bug the fix is about.

## 1. Setup

Replace `$W` with an empty folder (on Windows: Git Bash, with `C:/…` paths). The script creates a `v2` repository with:

- a `main` line of 16 commits where `calc.txt` gets a bug at commit 11 (`answer=41`), for the bisect;
- two merged feature branches, for first-parent history;
- `lines.txt`, changed on a few lines over several commits and renamed, for the line history;
- a stash with a tracked change and an untracked file, for "Apply this file";
- a binary, a symbolic link and a non-UTF-8 file, for the files at a commit.

```bash
git init -q -b main $W/v2 && cd $W/v2
printf 'answer=42\n' > calc.txt
printf 'line %s\n' $(seq 1 30) > lines.txt
git add -A && git commit -qm "base"
for i in $(seq 2 16); do
  echo "step $i" >> log.txt
  [ $i -eq 11 ] && printf 'answer=41\n' > calc.txt
  [ $i -eq 5 ] && sed -i.bak 's/^line 10$/line 10 (edited)/' lines.txt
  [ $i -eq 8 ] && sed -i.bak 's/^line 12$/line 12 (edited)/' lines.txt
  rm -f lines.txt.bak; git add -A && git commit -qm "commit $i"
done
git mv lines.txt notes.txt && git commit -qm "rename lines to notes"
sed -i.bak 's/^line 11$/line 11 (after rename)/' notes.txt && rm notes.txt.bak && git commit -qam "edit notes after rename"
git switch -qc feat/a HEAD~5 && echo a > a.txt && git add a.txt && git commit -qm "feat a" && git switch -q main
git merge -q --no-ff feat/a -m "merge feat/a"
git switch -qc feat/b && echo b1 > b.txt && git add b.txt && git commit -qm "feat b 1" && echo b2 >> b.txt && git commit -qam "feat b 2" && git switch -q main
git merge -q --no-ff feat/b -m "merge feat/b"
printf '\x00\x01\x02binary' > blob.bin && ln -s notes.txt link-to-notes && printf 'caf\xe9 cr\xe8me\n' > latin1.txt
git add -A && git commit -qm "assets"
echo "stashed change" >> notes.txt && echo "new file" > stashed-new.txt && git stash push -q -u -m "two files"
```

On Windows without `core.symlinks`, `link-to-notes` is a plain file: expected, skip the symbolic link item.

For **the hook `PATH`**: Node.js installed through Homebrew, nvm or Volta (macOS), or the official installer / nvm-windows / Volta (Windows), and a hook in `v2` that calls them:

```bash
printf '#!/bin/sh\nnode --version && npx --version\n' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

With husky in a real project (`npm i -D husky && npx husky init`, `.husky/pre-commit` containing `npx --no-install lint-staged` or `npm test`), the same items apply.

## 2. Checklist

Tick each item; "Expected" describes the correct behavior. `⌘` = `Ctrl` and `⌥` = `Alt` on Windows. After each write, check the actual state in a terminal (`git status`, `git log --oneline --graph --all`, `git stash list`): the UI must say the same as Git. The command log (status bar → "Log") must list every command run.

### Persistent undo (M7-1, M7-2)

- [ ] **Undo after a restart**: commit, create a branch, discard a modified file, then **quit yaggui** (`⌘Q`, not just close the tab) and start it again — Expected: the "Operation history" dropdown shows the three operations under **Earlier sessions**, with their date; `⌘Z` three times undoes them in order (discarded file back with its content, branch deleted, commit undone with its changes staged again); `⌘⇧Z` redoes them.
- [ ] **New operations after a restart** — Expected: they go under **This session**, above the earlier ones; undoing goes through this session's entries first, then the earlier ones.
- [ ] **Refs moved while yaggui was closed**: commit in yaggui, quit, `git commit --allow-empty -m outside` in a terminal, start again — Expected: the entry is grayed with "cannot be restored" and its reason in the tooltip; `⌘Z` shows "Cannot undo" naming `refs/heads/main`; nothing changes in the repository.
- [ ] **Objects pruned while closed**: discard a modified file, quit, `git reflog expire --expire=now --all && git gc --prune=now`, start again — Expected: the entry is grayed, the reason is "what it needs was deleted by Git's garbage collection since"; `⌘Z` refuses and does not touch the file.
- [ ] **M7 writes survive the restart**: create a fixup (§ Fixup) and apply one file from a stash (§ Stash), quit, start again — Expected: both entries are in **Earlier sessions**; `⌘Z` undoes the stash file (the working tree file comes back as it was), then the fixup commit (its changes staged again); the stash is still in `git stash list`.
- [ ] **Closing the tab is not a restart, forgetting the repository is**: close and reopen the tab — Expected: the history is unchanged. Remove the repository from the welcome screen, then open it again — Expected: the history is empty.
- [ ] **Bounds**: no visible check needed (100 entries per repository, none older than 30 days); note any entry you would have expected to see that is missing.

### Fixup and autosquash (M7-3)

- [ ] **Create a fixup**: change `log.txt`, stage it, right-click "commit 9" → **Create a fixup for this commit** — Expected: a commit `fixup! commit 9` on `main`, toast "Fixup … created for …"; `⌘Z` undoes it and the change is staged again. Without staged changes the menu entry is disabled with "Stage the changes of the fixup first".
- [ ] **From the palette**: select a commit, palette "Create a fixup for the selected commit" — Expected: same result.
- [ ] **Commit off the branch**: right-click a commit of `feat/b` while on `main` — Expected: refused with "This commit is not on the current branch…", nothing committed.
- [ ] **Fixup of a fixup** — Expected: `fixup! fixup! commit 9`, which the autosquash puts under "commit 9" too.
- [ ] **Autosquash** (commit menu or palette "Autosquash the fixups…") — Expected: the interactive rebase opens with each fixup moved under its target as "Fixup" and the notice "N fixups moved under their targets"; nothing runs before "Start"; after it, `git log --oneline` has no `fixup!` commit left. A fixup whose target is not in the list stays in place with its notice.
- [ ] **Hooks**: with the `pre-commit` hook of §1 failing (`exit 1`), the fixup is refused with the hook output, like a commit.

### One file from a stash (M7-4)

- [ ] **Tracked file**: open the stash "two files", hover `notes.txt` → **Apply this file to the working tree** (or right-click) — Expected: `notes.txt` gets the stashed line, unstaged; `stashed-new.txt` is not created; `git stash list` still has the stash.
- [ ] **Untracked file**: same on `stashed-new.txt` (untracked section) — Expected: the file is created, untracked; the stash is kept. Applying it again: refused, "already exists in your working tree".
- [ ] **Local changes in the way**: modify `notes.txt`, then apply it from the stash — Expected: refused with "Your local changes to "notes.txt" would be overwritten…", nothing changed.
- [ ] **Conflict**: commit a change on the last line of `notes.txt`, then apply it from the stash — Expected: "notes.txt" from the stash conflicts…; the file is in the conflicts list (3-way editor available); `⌘Z` gives the file back as it was before and clears the conflict; `⌘⇧Z` brings the conflict back.
- [ ] **Undo after a success** — Expected: the working tree file is back as it was before (content and mode), the stash untouched.

### First-parent history (M7-5)

- [ ] **Toggle** (toolbar **First parent**, palette, `⌘⌥R`) on `v2` — Expected: the commits of `feat/a` and `feat/b` disappear behind their merges, the merges stay as rows without the side line; the filter bar says "First-parent history"; `⌘⌥R` again brings back the full graph. **(win)** On a layout where `Ctrl+Alt` is AltGr, note whether the shortcut reaches the app.
- [ ] **Kept per repository**: turn it on in `v2`, open another repository — Expected: full graph there; close and reopen `v2`, then restart yaggui — Expected: still first-parent in `v2`.
- [ ] **Search** (`⌘F`, text "feat b") — Expected: the search bar says "First-parent history only" and finds no `feat b` commit; **Show full history** leaves the mode and the search finds them.
- [ ] **Jump outside**: select "merge feat/b", click its second parent in the commit details — Expected: toast "… is not in the first-parent history" with **Show full history**, which reveals the commit.
- [ ] **With bisect markers**: run the bisect of the next section with the mode on — Expected: the markers of the commits shown stay on their rows; a tested commit outside the first-parent rows (bisect does not follow first parents) is reached from the banner link through the "not in the first-parent history" toast. Note anything confusing.
- [ ] **Large repository** (`git/git` or `linux`): first opening in the mode, then scrolling — Expected: as fast as the full graph (P-02 / P-04, [V1-audit.md](V1-audit.md) §6).

### Preferences import / export (M7-6)

- [ ] **Export** (Preferences › **Export…**, or palette) on machine A after changing the theme, the text size and one shortcut — Expected: native save dialog; the JSON file contains the preferences and the custom shortcut, and neither the Git path nor the editor / terminal / tools; the toast says what was left out. Cancelling the dialog writes nothing and shows nothing.
- [ ] **Import** on machine B (the other OS, ideally) — Expected: the preview lists each preference with its old and new value, the shortcut changes, and the machine-specific keys as "Left out"; nothing changes before **Import**; after it, the theme, size and shortcut apply at once, and `keybindings.json` contains the shortcut. A file that changes nothing says so.
- [ ] **Shortcuts across OSes**: a shortcut with `⌘` exported on macOS — Expected: on Windows it is `Ctrl` (shortcuts are stored as `Mod+…`).
- [ ] **Invalid file** (truncated JSON, `"version": 99`, a text file) — Expected: refused with a message naming the problem; nothing changed.

### History of a line range (M7-7)

- [ ] **From the blame** of `notes.txt`: click line 10, Shift-click line 12, **History of lines 10–12** — Expected: the commits "edit notes after rename", "commit 8", "commit 5" and "base", each with its diff limited to these lines; the history goes back past the rename ("renamed from lines.txt"); the oldest entry says the lines appear there.
- [ ] **From a commit diff**: gutter selection in the diff of "commit 8", then **Line history** — Expected: same view, starting at that commit.
- [ ] **Working tree lines**: add two lines at the top of `notes.txt` (unsaved in the repo), then the history of the lines that were 10–12 — Expected: "In HEAD: lines 10–12 (working tree: 12–14)"; the history is the same as above. Lines that only exist in the working tree: refused, "These lines are not committed yet".
- [ ] **Stop on a long history** (`git/git`, a range in `Makefile` or `diff.c`) — Expected: "Following the lines through the history…" with **Stop** (`Esc`); stopping shows "Search stopped." and **Search again**; the app stays responsive; no `git log` process is left (Activity Monitor, Task Manager).
- [ ] **(win)** CRLF file and a path with spaces and accents — Expected: same results as in a terminal (`git log -L 10,12:"<path>"`).

### Files at a commit (M7-8)

- [ ] **Open** from the commit details (**Browse files at this commit**), the graph menu and the palette — Expected: folders first, virtualized list; keyboard navigation; the file opens read-only with highlighting.
- [ ] **Kinds of files** at "assets": `blob.bin` (binary, size, no preview), `link-to-notes` (symbolic link, **Go to the target**), `latin1.txt` ("Not UTF-8: shown as Windows-1252", `café crème` readable), an LFS pointer and a submodule if the repository has them.
- [ ] **Save as…** — Expected: native save dialog with the file name; the saved file is byte-identical to `git show <sha>:<path> > file`; **(win)** a CRLF file keeps the bytes of the commit (no conversion). An existing file is only replaced after the dialog's own confirmation.
- [ ] **History and blame** of the file from the viewer — Expected: they start at that commit.
- [ ] **Large tree** (`linux` at any commit, `drivers/`) — Expected: the folder lists quickly and scrolls without stutter.

### Assisted bisect (M7-9)

- [ ] **Start from the graph**: right-click `main` → **Start bisect** › **Mark as bad**, then "base" → **Bisect** › **Mark as good** — Expected: banner "Testing <commit>", "about N steps left · M commits to test"; markers "bad", "good", "testing" in the graph; HEAD detached on the commit under test (`git status`).
- [ ] **Steps from the banner**: look at `calc.txt` in a terminal at each step: `answer=42` → **Good**, `answer=41` → **Bad**; once **Skip** — Expected: after about 4 steps, "First bad commit found": "commit 11", with a jump to it and a toast; "first bad" marker on its row.
- [ ] **End bisect** — Expected: confirmation, then HEAD back on `main` (`git status`), no markers left.
- [ ] **Local changes**: modify `calc.txt`, then mark — Expected: "Stash your changes to bisect?"; **Stash and continue** stashes and marks.
- [ ] **Wrong order**: mark a good commit that descends from the bad one — Expected: refused ("A good commit is not an ancestor of the bad one…"), and no mark recorded (`git bisect log`).
- [ ] **Interrupted bisect found again**: start a bisect, mark one step, **quit yaggui**, start again — Expected: the banner is back with the same marks and the commit under test. Same with a bisect started in a terminal (`git bisect start main <base sha>`) while yaggui is open.
- [ ] **Undo during a bisect** — Expected: `⌘Z` of a commit or a branch operation waits for the end of the bisect ("an operation is in progress"); undoing a discard or a stash file works.

### Git hooks and `PATH` (PR #58)

- [ ] **(mac)** **App started from the Dock or the Finder** (not from a terminal), Node through Homebrew / nvm / Volta, the `pre-commit` hook of §1 — Expected: the commit succeeds; the command log shows the hook output with the Node and npx versions, not "node: command not found".
- [ ] **(mac)** **Husky project** (`.husky/pre-commit` calling `npx`) — Expected: same; the fixup and the amend run the hook too.
- [ ] **(mac)** **Slow or interactive shell startup** (`sleep 10` added to `~/.zshrc` for the test) — Expected: yaggui opens normally; the first Git command waits at most 5 s, then hooks run with the app's own `PATH` (the hook may then fail: expected). Remove the `sleep` afterwards.
- [ ] **(mac)** **External editor and terminal** (`code`, `subl` installed with Homebrew) — Expected: they open when yaggui is started from the Dock.
- [ ] **(win)** **Hook calling `npx`** (Git for Windows runs it through `sh`) — Expected: the commit succeeds; Windows is not concerned by the fix (GUI apps get the user's full `PATH`), this checks nothing regressed.

## 4. Known limitations (accepted for M7)

- **Persistent undo**: undo is refused for an entry whose refs moved or whose backup objects were pruned, by design; a full `git gc` can make old discards unrestorable. The journal is kept per repository in `yaggui.db` and removed with the repository.
- **One file from a stash**: on a conflict the status bar records the operation as completed (the conflict itself is shown and undoable); a file deleted on your side since the stash is refused rather than restored.
- **Fixup**: only `fixup!` is recognized by the autosquash, not `amend!` or `squash!`.
- **First-parent**: bisect, comparisons and merge-base use the full history; their commits can be outside the rows shown.
- **Line history**: follows the lines as `git log -L` does: lines moved or copied from another file are not followed.
- **Bisect**: no palette entries for good / bad (banner and graph only); `git bisect run` and custom terms are not offered (terms set in a terminal are respected).

## 6. Expected report

For each failing item, provide:

- the OS, the step, and what was observed (a screenshot if it is visual);
- the command log entry (status bar → "Log": command, exit code, stderr);
- the output of `git status` and `git log --oneline --graph --all -10`.

Depending on the item, add:

- persistent undo: the content of the operation history before and after the restart;
- bisect: `git bisect log`;
- hook `PATH`: how yaggui was started, the shell (`echo $SHELL`), how Node is installed, and the hook output from the command log;
- preferences: the exported JSON file.
