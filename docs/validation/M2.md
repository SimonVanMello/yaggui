# Manual validation of milestone M2

Guide for validating M2 (everyday writes: staging and commit, branches, stash, tags, network, clone / init, preferences) on **macOS** and **Windows** before starting M3. Allow about 1 h per OS. Prerequisites, launching and database location: same as [M0.md](M0.md) §1–2; checklist conventions: [M1.md](M1.md) §2.

```bash
git pull && pnpm install
pnpm tauri dev                          # dev mode
pnpm tauri build --debug --no-bundle    # binary with the production CSP (use it to validate screens)
YAGGUI_CONFIG_DIR=/some/empty/folder pnpm tauri dev   # isolated session: no existing repositories or preferences
```

The nonce-based CSP does not exist under `pnpm tauri dev`: a screen whose styles only work in dev shows up only with the `build --debug` binary.

## 1. Test repositories

Everything happens locally, with no account and no network. Replace `$W` with an empty folder (on Windows: Git Bash, with `C:/…` paths).

```bash
git init -q --bare -b main $W/remote.git
git clone -q file://$W/remote.git $W/work && cd $W/work
for i in 1 2 3; do echo "line $i" >> a.txt; git add a.txt; git commit -qm "seed $i"; done
git push -q origin main
git clone -q file://$W/remote.git $W/other      # "a colleague": used to move the remote
```

| Repository | Used for |
|---|---|
| `$W/work` (open in yaggui) | everything except clone / init; its remote is `$W/remote.git` |
| `$W/other` (in a terminal) | pushing commits, deleting remote branches, creating divergence |
| A real HTTPS remote and a real SSH remote (GitHub, GitLab, self-hosted server), with a throwaway repository | only the **(mac)** / **(win)** items of §3: `file://` goes through neither a credential helper nor ssh |
| A normal-sized personal repository | everyday use, hooks, `autocrlf` (Windows) |

To simulate a credentials failure without an account: `python3 -m http.server` does not work, but any server answering `401` to `GET /x.git/info/refs` is enough (`http://127.0.0.1:8099/x.git`).

## 2. Checklist

Tick each item; "Expected" describes the correct behavior. `⌘` = `Ctrl` on Windows. After each write action, check the actual state in a terminal (`git status`, `git log --oneline --graph --all`): the UI must say the same thing as Git. The Command log (status bar → Log) must contain every command run, with its duration and exit code.

### Staging and commit

- [ ] **Modify `a.txt` in an editor** — Expected: within a second, a "Work in progress" node in the graph, file under "Unstaged" with +/−.
- [ ] **Stage**: button on hover, `Space` on the row, drag to "Staged", "Stage all" — Expected: the file moves to the other list; `git diff --cached` confirms it; "Unstage all" does the reverse.
- [ ] **Stage a hunk and a line** (buttons in the diff; keyboard: ↑/↓, `Space`, Shift+↑/↓, Enter) — Expected: only the selection goes into the index; the rest of the file is still under "Unstaged" (file listed in both).
- [ ] **Untracked, deleted, renamed file** (`git mv`) — Expected: correct statuses; unstaging a rename restores the source.
- [ ] **Discard changes** (file, hunk, line) — Expected: a confirmation that names the file and shows the effect; after confirming, the file goes back to its indexed state. A backup is written first (`<config>/backups/<id>/`).
- [ ] **Commit**: summary (/72 counter), description, `⌘↵` — Expected: the commit appears at the top, the form clears, the WIP disappears, success toast. Commit without a summary: button greyed out.
- [ ] **Amend** ("Amend previous commit" checkbox) — Expected: the message is prefilled; the commit is replaced, not added.
- [ ] **"Push after commit"** — Expected: commit then push, the ↑ counter drops to 0; if the push fails, the commit stays and the error is shown.
- [ ] **Missing identity** (`git config --unset user.email` locally, with no global value) — Expected: readable `identityUnknown` error, with a way to set it.
- [ ] **Failing `pre-commit` hook** (`echo 'echo nope >&2; exit 1' > .git/hooks/pre-commit; chmod +x …`) — Expected: no commit is made, the full hook output is readable in the panel; **(win)** the hook runs (Git for Windows launches it through its `sh`).
- [ ] **File modified while its diff is open** (save from the editor while a line selection is active) — Expected: stage / discard refused with "The file changed" and a refresh, never a wrong patch applied.
- [ ] **Merge in progress with conflicts** (created in a terminal) — Expected: commit refused (`unresolvedConflicts`), "Unstage all" keeps the merge in progress.

### Branches and checkout

- [ ] **Double-click on a local branch** (sidebar) — Expected: checkout, HEAD pill moved, branch picker updated.
- [ ] **Double-click on a remote branch with no local branch** — Expected: creates the local branch tracking it (`git branch -vv` shows the upstream).
- [ ] **Checkout with a dirty tree** — Expected: dialog offering "Stash, check out, then pop" / "Bring the changes along"; each of the two choices ends in the announced state. If a modified file conflicts with the target: clear error, nothing is lost.
- [ ] **Create** (⌘B, graph menu): live name validation (`a b`, `a..b`, `-x`, `x.lock`, duplicate) — Expected: error message before submitting, button greyed out; "checkout" option honored.
- [ ] **Rename, delete** (local, then the remote one too) — Expected: deleting an unmerged branch asks for explicit confirmation; remote deletion removes the branch from `remote.git` (`git -C $W/remote.git branch`).
- [ ] **Set / remove upstream** — Expected: `↑↓` and "upstream deleted" reflect the config.
- [ ] **Detached HEAD** (checkout of a commit) — Expected: the branch picker shows "Detached HEAD" and the SHA; committing works; Pull / Push buttons greyed out.
- [ ] **Branch picker** (toolbar): search, arrows, ↵ — Expected: same checkouts as above.

### Stash

- [ ] **⌘⇧S** with changes + an untracked file — Expected: options (include untracked files, keep index, message); the stash appears in the sidebar and the graph, the tree is clean.
- [ ] **Preview** of a stash (click) — Expected: files and diff, including untracked files.
- [ ] **Apply / pop / drop / rename / create a branch from the stash** — Expected: Git state as expected; a conflicting pop keeps the stash and shows the error. The toolbar Pop button pops the latest one (⌘⇧⌥S).
- [ ] **Drop a stash** — Expected: confirmation (can be turned off in preferences) naming the stash.

### Tags

- [ ] **Create a tag**, lightweight then annotated (graph menu, on a commit) — Expected: tag pill on the right commit; the annotated one carries its message (`git show <tag>`).
- [ ] **Delete a local tag** — Expected: confirmation, pill removed.
- [ ] **Push a tag, delete a remote tag** (tag menu) — Expected: `git -C $W/remote.git tag` confirms it.

### Network

- [ ] **Push** (⌘⇧P) of a local commit — Expected: status bar with phase, percentage and throughput (`MB/s`) if the transfer is long enough to have any; `remote.git` receives the commit; ↑ drops to 0.
- [ ] **First push of a branch without upstream** — Expected: `noUpstream` error with the "Set upstream and push" action; the action pushes and sets the upstream (`git config branch.<b>.remote`).
- [ ] **Fetch** (⌘⇧F, menu: one remote or all) — Expected: remote branches updated, ↓ shows up. **Prune** (on by default): delete a branch in `remote.git` (`git branch -D`), fetch → it disappears from the sidebar; prune turned off in preferences → it stays.
- [ ] **Auto-fetch** (preferences: short interval, e.g. 1 min) — Expected: fetch triggers on its own without freezing the UI; turned off in preferences → nothing anymore.
- [ ] **Refused ff-only pull**: one local commit + one commit pushed from `other`, fetch, ⌘⇧L — Expected: toast "Your branch and its upstream diverged: a fast-forward is impossible. Pull with merge or rebase.", history unchanged.
- [ ] **Pull with rebase, then with merge** (Pull button menu) — Expected: rebase → linear history; merge → merge commit. The menu's default strategy follows the preferences, otherwise `pull.rebase` / `pull.ff`.
- [ ] **Conflicting pull** — Expected: `conflicts` error (the `pullConflict` of M2-5, unified in M3-5) stating whether it is a rebase or a merge; the operation in progress is visible, resolution works as for a merge (see [M3.md](M3.md)).
- [ ] **Pull on a dirty tree** touching a modified file — Expected: readable refusal (`dirtyWorktree`), tree intact.
- [ ] **Rejected push** (the remote moved ahead) — Expected: `pushRejected` with "Pull then push"; the action does both and stops if the pull fails.
- [ ] **Confirmed force push (with lease)** on an unprotected branch, after an amend — Expected: the confirmation lists the overwritten commits and the command; after confirming, `remote.git` has the amended commit. If the remote moved since the last fetch: refused by Git (lease), nothing is overwritten.
- [ ] **Force push on `main`** (protected by default) — Expected: refused without calling Git, `remote.git` intact. Remove `main` from protected branches (preferences) and retry: confirmation is asked (it can never be turned off).
- [ ] **Unreachable remote** (`git remote add dead file:///nowhere.git`, fetch that remote) — Expected: `remoteNotFound` or `hostUnreachable` (with "Retry"); the UI stays responsive.
- [ ] **Cancel** a long operation (see **(mac)** / **(win)** below for a real network; locally: `git config remote.origin.uploadpack 'sleep 10; git-upload-pack'`, fetch, Cancel button) — Expected: the operation stops in under a second, no `git` process is left (`ps` / Task Manager), the repository state is sound.

### Clone and init

- [ ] **Clone** (welcome page, or palette "Clone a repository…") `file://$W/remote.git` into an empty folder — Expected: the folder name is suggested from the URL, "Created at …" is shown; at the end the repository opens in the tab, with a correct graph. No password is asked for anywhere.
- [ ] **Options**: branch (`feat/x`), shallow clone, submodules — Expected: `git branch --show-current`, `git rev-list --count HEAD`, submodules present.
- [ ] **Errors**: non-empty folder, nonexistent URL, missing branch, closed port (`http://127.0.0.1:1/x.git`), 401 — Expected: a readable message in the dialog for each case, destination folder not created (or cleaned up), "Retry" only for the unreachable host.
- [ ] **Cancel a clone** in progress (large repository, or slow server) — Expected: immediate stop, folder deleted if the clone created it.
- [ ] **Init** (welcome page) with default branch, `.gitignore`, README — Expected: `.git` created, files written, never overwritten if they exist; invalid branch (`feat/`, `a..b`) refused before the call; the repository opens.
- [ ] **Init inside an existing repository** — Expected: `alreadyRepository`.
- [ ] **Recent folders**: the dialogs suggest the last destination folder.

### Preferences (⌘, or the gear icon)

- [ ] **Appearance**: theme System / Light / Dark, High contrast, density, language, fonts, size — Expected: applied immediately, without a reload; unknown font → falls back to the default font without breaking the layout; `Mod+,` reopens the screen.
- [ ] **Git binary**: enter an invalid path, then a valid one, then "Auto-detect" — Expected: invalid = error, nothing saved, previous Git still used; valid = version shown; the status bar shows the Git version in use.
- [ ] **Behavior**: auto-fetch (+ interval), prune, pull strategy, protected branches (add, remove, "Restore defaults"), confirmations (discard, tag deletion, stash drop) — Expected: each setting applies on next use; "Force push" stays locked.
- [ ] **Quit and relaunch the app** — Expected: theme, density, fonts, language, strategy, protected branches and open tabs are restored with no theme flash. Database: `yaggui.db`, `preferences` table.
- [ ] **Terminal** (gear → "Configure…") — Expected: choice kept, the toolbar "Terminal" button uses it.

### macOS- and Windows-specific items

These items cannot be tested with `file://`: they need a real remote and the machine's real configuration.

- [ ] **(mac)** **HTTPS auth through a credential helper**: `git config --global credential.helper` must be `osxkeychain`. Sign in once from a terminal (`git ls-remote https://…` of a private repository), then in yaggui: clone, fetch and push the same repository — Expected: no prompt, everything works. Remove the entry from the keychain (Keychain Access) and fetch again — Expected: `authFailed` with the "credential helper" hint, no blocked window.
- [ ] **(win)** **HTTPS auth through a credential helper**: `credential.helper` must be `manager` (Git Credential Manager, shipped with Git for Windows). Same scenario as above — Expected: after the initial sign-in, no prompt; without credentials, `authFailed` and no blocking GCM window (`GIT_TERMINAL_PROMPT=0`; GCM may still open its window: if it does, note the behavior and whether the operation unblocks when it is closed).
- [ ] **(mac)** **SSH through ssh-agent**: `ssh-add -l` lists the key (`ssh-add --apple-use-keychain ~/.ssh/id_ed25519` so it survives a restart). Clone `git@github.com:…`, fetch, push — Expected: no passphrase prompt in yaggui. With an empty agent (`ssh-add -D`): `authFailed` with the "ssh-add" hint.
- [ ] **(win)** **SSH through ssh-agent**: the "OpenSSH Authentication Agent" service must be running (`Get-Service ssh-agent`) and the key added (`ssh-add`); if Git for Windows uses its own `ssh`, check `git config core.sshCommand` (e.g. `C:/Windows/System32/OpenSSH/ssh.exe` to share the Windows agent). Same scenarios — Expected: same as macOS.
- [ ] **(mac)** **(win)** **First connection to an unknown SSH host** (remove its line from `known_hosts`) — Expected: the operation fails fast with a readable message (the "fingerprint?" question cannot be asked without a terminal); after `ssh -T git@host` in a terminal, everything works. Note the message shown.
- [ ] **(mac)** **(win)** **Cancellation on a real network**: clone a large repository (`git clone https://github.com/git/git.git`) or fetch a large remote, then Cancel mid-transfer — Expected: progress stops in under a second, no `git` / `git-remote-https` / `ssh` is left (`ps aux | grep git`; Task Manager), the clone folder is deleted, a new clone at the same location works.
- [ ] **(mac)** **(win)** **Network down** (airplane mode) during a fetch — Expected: `hostUnreachable` error within a reasonable time (no freeze), "Retry" works once the network is back.
- [ ] **(win)** **`core.autocrlf=true`** (Git for Windows default): modify one line of a file with LF line endings in the index, stage that line alone, then a hunk, then discard a hunk — Expected: only the selection is affected, no whole-file difference, `git diff --cached` as expected.
- [ ] **(win)** **`core.fileMode=false`** — Expected: no phantom mode change in the panel, staging a file does not change its mode.
- [ ] **(win)** **Long paths**: `git config core.longpaths false`, create a file whose path exceeds 260 characters, stage it — Expected: `pathTooLong` error with the command to run (`core.longpaths true`); once set, stage and commit work.
- [ ] **(win)** **`index.lock` after cancellation**: start a commit with a slow hook (`sleep 20`), cancel, then stage again — Expected: no leftover `index.lock` (`.git/index.lock` absent); if present, note it with the command that left it.
- [ ] **(mac)** **(win)** **`index.lock` left by another process** (`touch .git/index.lock`, then stage in yaggui) — Expected: error naming the lock and offering to retry, never deleted automatically.
- [ ] **(mac)** **File system case sensitivity**: branch `Feat/x` then `feat/x`; file renamed by changing only its case — Expected: no crash; note the behavior.

### Themes

- [ ] **Graphite and Paper** on every screen above (commit panel, confirmations, toasts and progress bar, clone / init dialogs, preferences, Pull / Push / Fetch menus) — Expected: correct contrast, readable error states, no visible hard-coded color.
- [ ] **Switch the theme while a network operation is running** — Expected: no effect on the operation, progress bar readable in both themes.
- [ ] **Compact density** — Expected: lists and forms stay usable, no clipped text.

## 3. Diff, keyboard and status performance (M2-7a, M2-7c)

- [ ] **P-05 · status**: in a large repository (e.g. `linux`, or `git/git`), modify a file in an editor — Expected: the WIP row and the file under "Unstaged" appear in under roughly 200 ms, without stutter. Backend measurement available: `cd src-tauri && YAGGUI_BENCH_REPO=<repo> cargo test --release --test status p05 -- --ignored --nocapture`. **(mac)** FSEvents latency adds to the 40 ms debounce.
- [ ] **Diff options** (diff bar): wrap lines, ignore whitespace, number of context lines, whole file — Expected: immediate effect, choices kept after a restart.
- [ ] **Side by side with line wrapping** on a file with long lines — Expected: both sides stay aligned (a line entering the view may realign one frame later), correct system fonts.
- [ ] **Whitespace ignored** — Expected: hunk and line buttons are disabled with an explanation (the displayed diff no longer matches the real hunks).
- [ ] **Keyboard line selection** in the diff of an unstaged file: ↑/↓ between changed lines, Space selects, Shift+↑/↓ extends, Enter stages, ⌫ / Del discards (with confirmation), Esc clears — Expected: works in WKWebView / WebView2; note whether the displayed key hint is unclear.
- [ ] **Hook writing a huge amount of output** (e.g. `yes | head -c 10000000` in `pre-commit`, then `exit 1`) — Expected: output truncated in the middle ("[...]") with a notice, no freeze.
- [ ] **Preview of a stash created with untracked files** — Expected: "Untracked files" list present.
- [ ] **(mac)** **SSH launched from a terminal**: launch yaggui from a terminal (`pnpm tauri dev` or the binary), empty agent (`ssh-add -D`) and a passphrase-protected key, then fetch an SSH remote — Expected: fast `authFailed` failure (git runs without a controlling terminal), no wait for a passphrase in the terminal.

## 4. Known limitations (accepted for M2)

- **No credentials window**: yaggui never asks for a password or passphrase (`GIT_TERMINAL_PROMPT=0`). Everything goes through Git's credential helper and ssh-agent; without them, the operation fails with `authFailed` and a hint. Git runs without a controlling terminal: even an app launched from a shell cannot wait for a passphrase.
- **Clone URL in the Command log**: the URL as typed, including any token (`https://user:token@…`), shows up in the command log (in memory only, never written to disk).
- **`notFastForward` without an action**: the toast explains that a pull with merge or rebase is needed but offers no button; the user goes through the Pull button menu.
- **`authFailed` without "Retry"**: the fix happens outside yaggui (terminal, keychain), so the button would come too early. To be reconsidered based on usage feedback.
- **Network progress**: Git only sends `--progress` when there is something to transfer; a local `file://` is too fast to see it, and a `fetch` with nothing new shows nothing.
- **Known gaps between the mock client (`pnpm dev`, Playwright tests) and the real backend**: the mock does not simulate prune (a branch deleted on the server never disappears there), has no `staleLease` (force push while the remote moved), logs `--force-with-lease` without `=<ref>:<sha>`, and accepts any clone URL (the real backend refuses `-x` and requires an absolute folder; the `auth`, `unreachable`, `notfound`, `slow` patterns in the URL decide the outcome). A remote named `offline` simulates an unreachable host there, `auth` a credentials refusal.
- **Screens not covered by a real capture**: the line discard confirmation and cancelling a clone over a real network are only validated by the Rust integration tests (a `git://` server that never answers) and the mock.
- **Advanced operations**: merge, interactive rebase, cherry-pick, revert, reset, conflicts: M3. A conflicting pull leaves the operation in progress, visible but to be finished in a terminal until M3 ships. Undo / redo: M4 (the button is greyed out).
- **Diff**: a sticky hunk header can still be truncated in a very narrow panel; no image comparison (F-085).

## 5. Reference measurements (Linux container, 4 vCPU, no GPU, `build --debug` binary)

| Flow (`file://` remote) | Measured |
|---|---|
| External change → WIP row and file under "Unstaged" | < 1 s (watcher) |
| Stage a file → commit → push | Git state as expected at each step, no perceived freeze |
| Fetch with prune, refused ff-only pull, rebase pull, confirmed force push, force push refused on `main` | Git state as expected |
| `file://` clone (4 commits) → repository open | < 1 s |
| Preferences: theme, density, prune, strategy, protected branch → relaunch | everything restored, SQLite as expected |

The Rust integration tests (`cargo test`) cover every write operation on a temporary fixture repository; M1 performance measurements (P-02 to P-08) are not affected by M2. P-05 (50,001 files, release): disk change → panel repainted ≈ 110 ms median, ≈ 150 ms worst case (backend 95 ms, front end 13 ms; before M2-7a: 244 ms backend).

Details of the verification on the real binary are in the M2 task PRs.

## 6. Expected report

For each failing item: OS, step, what was observed (screenshot if visual), the Command log entry (status bar → Log: command, exit code, stderr) and, for network items, the remote type (GitHub HTTPS / SSH, GitLab, self-hosted server) and the output of `git config --global --get-regexp 'credential|core.sshCommand'`.
