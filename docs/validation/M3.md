# Manual validation of milestone M3

Guide for validating M3 (advanced operations: merge, simple and interactive rebase, cherry-pick, revert, reset, operation in progress, conflicts and the 3-way merge editor) on **macOS** and **Windows** before starting M4. Allow about 1 h 30 per OS. Prerequisites, launching and database location: same as [M0.md](M0.md) §1–2; checklist conventions: [M1.md](M1.md) §2.

```bash
git pull && pnpm install
pnpm tauri dev                          # dev mode
pnpm tauri build --debug --no-bundle    # binary with the production CSP (use it to validate screens)
YAGGUI_CONFIG_DIR=/an/empty/folder pnpm tauri dev   # isolated session: none of the existing repositories or preferences
```

The nonce-based CSP does not exist under `pnpm tauri dev`. The 3-way editor (CodeMirror) injects `<style>` elements: validate it **with the `build --debug` binary**, not only in dev.

## 1. Test repositories

Everything is local, with no account or network. Replace `$W` with an empty folder (on Windows: Git Bash, with `C:/…` paths). The script creates a `work` repository whose `main` diverges from its remote on three files (content, deleted / modified, binary), plus two branches for rebase and cherry-pick.

```bash
git init -q --bare -b main $W/remote.git
git clone -q file://$W/remote.git $W/work && cd $W/work
printf 'const greeting = "hello";\nconst count = 1;\n' > app.js
printf '# Notes\n\nold notes\n' > notes.md
printf '\x89PNG\r\n\x1a\nbase' > logo.png
printf 'one\r\ntwo\r\n' > crlf.txt
git add -A && git commit -qm initial && git tag v1.0 && git push -q origin main v1.0

# "a teammate" pushes to main
git clone -q file://$W/remote.git $W/other && cd $W/other
printf 'const greeting = "bonjour";\nconst count = 1;\n' > app.js
git rm -q notes.md && printf '\x89PNG\r\n\x1a\ntheirs' > logo.png
printf 'one\r\ntwo (theirs)\r\n' > crlf.txt
git add -A && git commit -qm "teammate" && git push -q origin main

# locally: the same files, changed differently, + two branches
cd $W/work
git switch -qc feature
printf 'const greeting = "salut";\nconst count = 1;\n' > app.js && git commit -qam "feature 1: greeting"
printf 'const greeting = "salut";\nconst count = 3;\n' > app.js && git commit -qam "feature 2: count"
git switch -q main
printf 'const greeting = "hi";\nconst count = 2;\n' > app.js
printf '# Notes\n\nnew notes\n' > notes.md && printf '\x89PNG\r\n\x1a\nours' > logo.png
printf 'one\r\ntwo (mine)\r\n' > crlf.txt
git commit -qam "mine" && git fetch -q
for i in 1 2 3 4; do echo "c$i" > "c$i.txt"; git add "c$i.txt"; git commit -qm "c$i"; done
```

| Repository | Used for |
|---|---|
| `$W/work` (open in yaggui) | all of §2; reset it by re-running the script, or with `git reset --hard <sha>` in a terminal |
| `$W/other` (in a terminal) | moving the remote |
| A real, normal-sized repository | real interactive rebase (an actual work branch), `core.autocrlf` (Windows) |

## 2. Checklist

Tick each item; "Expected" describes the correct behavior. `⌘` = `Ctrl` and `⌥` = `Alt` on Windows. After each write action, check the actual state in a terminal (`git status`, `git log --oneline --graph --all`): the UI must say the same thing as Git. The Log (status bar → Log) must contain every command run, with its duration and exit code.

### Merge

- [ ] **Drag `feature` onto `main`** (sidebar, then graph pill) — Expected: menu "Merge feature into main… / Rebase feature onto main / Fast-forward main to feature"; the dialog offers ff / no-ff / squash, and the last choice is remembered.
- [ ] **No-ff merge without conflicts** (on a fresh copy) — Expected: merge commit with two parents, message "Merge branch 'feature'" or the one entered.
- [ ] **Squash merge** — Expected: a single-parent commit, with a `Squashed commit…` message prefilled and editable; a squash that brings nothing leaves the merge in progress with "nothing to commit" and the "Abort merge" action.
- [ ] **Fast-forward only on diverged branches** — Expected: `notFastForward` with the "Merge instead…" action.
- [ ] **Merge with a local change to an affected file** — Expected: `dirtyWorktree` refusal naming the file, tree untouched.
- [ ] **Merge into Y (Y not current)** — Expected: the confirmation announces the checkout of Y before the merge; final state correct.

### Rebase

- [ ] **Rebase `feature` onto `main`** (drag or palette) — Expected: "Rebase n/m" progress in the banner and the status bar; linear history, `feature` still checked out.
- [ ] **Rebase of a non-current branch** — Expected: yaggui checks out the rebased branch (the dialog says so), not the target.
- [ ] **Rebase with tracked changes** — Expected: `dirtyWorktree` refusal; with only untracked files, the rebase goes through.

### Cherry-pick and revert

- [ ] **Cherry-pick two commits** (⌘-click in the graph, drag the selection onto a pill) — Expected: applied oldest to newest, regardless of selection order.
- [ ] **Cherry-pick of an already applied commit** — Expected: `emptyCommit` with the "Skip" action; the banner stays until it is skipped.
- [ ] **Cherry-pick or revert of a merge** — Expected: parent choice dialog; the revert keeps the chosen side.
- [ ] **Revert of a simple commit** — Expected: `Revert "…"` commit on top, message editable in the continue dialog when there is a conflict.

### Reset

- [ ] **Commit menu → Reset ▸ soft / mixed / hard** — Expected: each mode is explained; in hard mode, the list of lost files (including an untracked file the target tracks); a backup is written first (`<config>/backups/<id>/`).
- [ ] **Confirmed hard reset** — Expected: HEAD and the tree at the target, lost files present in the backup.

### Operation in progress (banner)

- [ ] **Operation started from a terminal** (a conflicting `git merge feature`, `git rebase -i`, `git cherry-pick`, `git bisect start`) — Expected: the banner appears in under a second, with the right summary and the right buttons (no Skip for a merge).
- [ ] **Continue disabled while conflicts remain**, with the explanation on hover; enabled as soon as the last file is resolved.
- [ ] **Abort** from the banner — Expected: confirmation showing the effect and the command (`git merge --abort`…); after confirming, the state from before the operation. The status bar says "Rebase aborted" (not "completed").
- [ ] **Palette** (⌘K): "Continue", "Skip", "Abort" only appear enabled during an operation; merge, rebase, cherry-pick, revert, reset only without one.

### Conflicts: one full scenario per operation

For each of the four operations below: trigger it, then go through conflicts panel → "Resolve…" → editor → Continue, and check the Git state.

- [ ] **Pull with merge** (Pull button ▸ Merge) on `$W/work` — Expected: toast "The pull stopped on conflicts: the merge is in progress" with "4 files in conflict" (`app.js`, `notes.md`, `logo.png`, `crlf.txt`), **same banner and same panel as a merge** started from the graph, status bar without an error state. Continue creates the two-parent merge commit (`HEAD^2` = `origin/main`).
- [ ] **Pull with rebase** — Expected: same thing with the "Rebase n/m" banner; labels: `origin/main` "rebasing onto", `main` "commit being replayed".
- [ ] **Merge `feature` into `main`** (content conflict on `app.js`) — Expected: 3-way editor titled with the branch names.
- [ ] **Rebase `feature` onto `main`** — Expected: stop at 1/2, then **a second conflict at 2/2 after Continue**, and the panel only lists the files of the new stop; Skip at 2/2 drops that commit; Abort brings `feature` back to its original SHA.
- [ ] **Cherry-pick both `feature` commits onto `main`** — Expected: stop on the first; Skip → stop on the second; Continue → a single commit applied.
- [ ] **Revert of a commit that added a file modified since** — Expected: "deleted / modified" conflict; "Accept the deletion" then Continue → revert commit without the file.

In the editor:

- [ ] **Per-hunk checkboxes**, both sides checked in order (badge 1 / 2), "Take all from X", editable result (typing in a hunk = resolved), `⌥↑` / `⌥↓` between conflicts, "N conflicts left" counter — Expected: the saved file (`⌘S`) is exactly the displayed result, then moves to the next unresolved file.
- [ ] **Deleted / modified** and **binary** (`logo.png`) — Expected: one card per side (size, image preview), explicit choice; "Take X's version" stages the right version (`git show :logo.png`).
- [ ] **Leaving with unsaved choices** (Graph button, `Esc`, "Resolve…" on another file) — Expected: confirmation.
- [ ] **External tool** (`git config merge.tool <tool>`) — Expected: the button names the tool; the tool opens on the file, and saving in it marks the file resolved; closed without saving, the file stays in conflict; Cancel from the status bar ends the wait. Without `merge.tool`: button disabled with an explanation.

### Interactive rebase

- [ ] **Palette "Interactive rebase from…"** then pick a base, or commit menu "Interactive rebase from here…" — Expected: list from newest to oldest, base excluded.
- [ ] **Actions** `p r s f d e` from the keyboard and buttons, reordering by drag and `⌥↑` / `⌥↓`, reword and squash messages edited inline (72 counter) — Expected: the "Result" preview matches the resulting history (`git log`), authors preserved, `#` lines in a message preserved.
- [ ] **Already pushed commits** — Expected: the confirmation lists them and warns about the force push.
- [ ] **Two `edit`s** — Expected: stop on the first (stop panel); Continue from the banner → toast "Rebase paused at step n/m" and status bar "Rebase paused", **not** "Rebase completed"; Continue again → "Rebase completed".
- [ ] **Conflict during the interactive rebase** — Expected: the 3-way editor opens on the first file; after resolving, Continue resumes.

### Remote tags

- [ ] **Tag menu → "Delete on the remote…"** — Expected: confirmation naming the tag, the remote and the command `git push origin --delete refs/tags/v1.0`; after confirming, `git -C $W/remote.git tag` no longer lists it, and the local tag stays.

### Themes

- [ ] **Graphite and Paper** on every screen above (banner, conflicts panel, 3-way editor, binary / deletion cards, interactive rebase view and its stop panel, merge / reset / parent / continue dialogs) — Expected: correct contrast, readable conflict markers, no visible hard-coded color.

## 3. macOS- and Windows-specific items

- [ ] **(win)** **Interactive rebase sequence editor**: Git for Windows runs `GIT_SEQUENCE_EDITOR` with **its own `sh`** (the one in `C:/Program Files/Git/usr/bin`), like its hooks and `git mergetool`. yaggui's editor only uses builtins of that shell (`read`, `printf`), no program from `PATH` (checked on Linux with an empty `PATH`, `tests/conflict_scenarios.rs`). The todo is in `%TEMP%\yaggui-rebase-<pid>-<n>\`, passed as `C:/…`. To validate: an interactive rebase with reword and reordering goes through; the `%TEMP%\yaggui-rebase-*` folder is gone at the end; same with a `%TEMP%` containing a space or an accent (`set TEMP=C:\Temp dir é` before launching yaggui). If Git is a **MinGit** (Git bundled by another tool, without `sh`), the interactive rebase fails: note the message.
- [ ] **(win)** **Line endings in conflicts** with `core.autocrlf=true` (Git for Windows default): conflict on a file stored with LF — Expected: the editor shows the content without stray `\r`; after `⌘S`, `git diff --cached` only shows the resolution, not a fully modified file. On `crlf.txt` (CRLF in the repository): `\r\n` bytes preserved (`git show :crlf.txt | od -c`).
- [ ] **(mac)** **(win)** **Mixed line endings** in a conflicted file — Expected (known limitation): saved with the majority line ending; note it if it is a problem.
- [ ] **(win)** **Long paths**: conflict on a file whose path exceeds 260 characters, `core.longpaths=true` — Expected: versions readable in the editor, resolution and Continue go through; with `core.longpaths=false`: readable `pathTooLong` error.
- [ ] **(mac)** **(win)** **Paths with spaces and Unicode** (`folder é/file ü.txt`) in conflict and in a hard reset backup — Expected: correct resolution and backup.
- [ ] **(mac)** **External `merge.tool`**: `opendiff` (FileMerge, Xcode), `meld`, `code --wait` (`git config mergetool.vscode.cmd 'code --wait --merge $REMOTE $LOCAL $BASE $MERGED'`) — Expected: the tool opens in the foreground, yaggui waits without freezing, resolved on close after saving; Cancel ends the wait (note whether the tool window stays open).
- [ ] **(win)** **External `merge.tool`**: Beyond Compare (`bc`), TortoiseMerge, `vscode`, `kdiff3` — same expectations; also check a tool path with spaces (`C:/Program Files/…`) and `mergetool.keepBackup` (`.orig` files).
- [ ] **(mac)** **(win)** **Aborting a merge or rebase during a slow hook** (`post-checkout` or `pre-rebase` with `sleep 20`) — Expected: stops in under a second, no `git` process left (`ps` / Task Manager); **(win)** no leftover `index.lock`.
- [ ] **(mac)** **(win)** **`core.commentChar=;`** and **`commit.cleanup=scissors`**: conflicting merge then Continue — Expected: clean prefilled message, correct commit.
- [ ] **(mac)** **Shortcuts** `⌥↑` / `⌥↓` (3-way editor, interactive rebase) and `⌘S` — Expected: no special character (`˚`, `∆`) inserted in the editor.
- [ ] **(mac)** **(win)** **Pointer drag** (sidebar → sidebar, sidebar → pill, graph rows → pill, interactive rebase rows) in WKWebView and WebView2 — Expected: visible drop indicator, no native text or image drag; **(mac)** `Ctrl`-click = right-click, `⌘`-click = multi-selection.
- [ ] **(win)** **`Shift+F10` and the menu key** on a graph row — Expected: yaggui's menu, not WebView2's.

## 4. Known limitations (accepted for M3)

- **Fast-forward "when possible"**: lacking an ancestry command, the action is always offered; a refusal (`notFastForward`) offers a merge.
- **Merge into a non-current Y**: yaggui checks out Y first; no fast-forward of a non-current branch.
- **No auto-scroll** of the sidebar or the graph during a drag.
- **Continuing a rebase** does not ask for a message (multi-step); merge, squash, cherry-pick and revert open the dialog.
- **3-way editor**: the three panes only scroll in sync when navigating between conflicts; mixed line endings saved with the majority one; opening a diff from the changes panel closes the editor without asking.
- **External tool**: `mergetool.keepBackup` is honored (`.orig` files); a terminal tool (vimdiff) has no TTY: it must be cancelled from the status bar.
- **Interactive rebase**: 200 commits at most, merges refused (no `--rebase-merges`), detached HEAD refused; closing the view during a stop leaves the rest to the banner, and the view does not reopen.
- **Bisect**: detection, skip and finish only (good / bad: later).
- **Double toast** when a bisect or `git am` continue / skip / abort fails (generic toast + typed toast); a successful bisect skip shows "Maintenance completed".
- **Known mock / real differences** (the mock serves `pnpm dev` and Playwright): a single conflict scenario (4 typed files) whatever the repository; reset does not refuse a `--soft` during a merge and ends any cherry-pick sequence; the hard reset preview ignores untracked files; the mock's external tool always succeeds. Mock triggers: path containing `conflict` (conflicts), `conflict-again` (second stop), `empty` (already applied commit), `overwrite` (merge, cherry-pick or revert refused over local changes it would overwrite), `no-mergetool`; `window.__yagguiMock.simulatePullConflict(id)` and `simulateRebaseConflict(id)`.

## 6. Expected feedback

For each failing item: OS, step, what was observed (screenshot if visual), the Log entry (status bar → Log: command, exit code, stderr), and the output of `git status` and `git log --oneline --graph --all -10` in a terminal. For the external tool: `git config --get-regexp 'merge|mergetool'`. For the sequence editor on Windows: `git --version`, `where sh` and the `%TEMP%` path.
