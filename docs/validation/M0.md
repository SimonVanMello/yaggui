# Manual validation of milestone M0

Guide to validate M0 on **macOS** and **Windows** before starting M1. Allow about 30 minutes per OS. Performance measurements are at the end of the document.

## 1. Prerequisites

| | macOS | Windows |
|---|---|---|
| OS | macOS 12+ (Intel or Apple Silicon) | Windows 10 (22H2) or 11, x64 |
| Native build tools | Xcode Command Line Tools: `xcode-select --install` | Visual Studio Build Tools 2022, "Desktop development with C++" workload (MSVC + Windows 10/11 SDK) |
| Webview | WKWebView (shipped with the OS) | WebView2 Runtime (preinstalled on Windows 11; otherwise the "Evergreen Bootstrapper" from Microsoft) |
| Rust | **≥ 1.93** through [rustup](https://rustup.rs) (`rustup update stable`), not Homebrew's Rust, which often lags behind | same, `stable-x86_64-pc-windows-msvc` toolchain |
| Node.js | 22 LTS or newer | same |
| pnpm | 10.x: `corepack enable` (the exact version comes from `packageManager` in `package.json`) | same |
| Git | 2.30+ (`git --version`); yaggui uses the system `git` | Git for Windows 2.30+ |

Quick check: `rustc --version`, `node --version`, `pnpm --version`, `git --version`.

Rust 1.93 minimum (set by `rust-version` in `src-tauri/Cargo.toml`): `specta` 2.0.0-rc.25 requires 1.93, Tauri 2.12 requires 1.90. With an older Cargo, the error is `feature 'edition2024' is required` (< 1.85) or `rustc X is not supported` (1.85–1.92). Fix: `rustup update stable`, and check that `which cargo` points to `~/.cargo/bin/cargo` (otherwise a Homebrew Rust takes precedence: `brew uninstall rust`).

## 2. Running the app

```bash
git clone https://github.com/SimonVanMello/yaggui.git yaggui && cd yaggui
pnpm install
pnpm tauri dev                               # full app in dev mode (Vite on 1420)
pnpm tauri dev -- -- /path/to/a/repository   # same, opening a repository at startup (F-001)
```

Installable build (release mode, unsigned: macOS asks for "Open anyway" through right-click → Open, Windows SmartScreen through "More info → Run anyway"):

```bash
pnpm tauri build                 # every format of the OS
pnpm tauri build --no-bundle     # binary only, faster (used for the P-01 measurement)
```

| | macOS | Windows |
|---|---|---|
| App | `src-tauri/target/release/bundle/macos/yaggui.app` and `bundle/dmg/yaggui_0.1.0_*.dmg` | `src-tauri/target/release/bundle/nsis/yaggui_0.1.0_x64-setup.exe` and `bundle/msi/yaggui_0.1.0_x64_en-US.msi` |
| Binary only | `src-tauri/target/release/yaggui` | `src-tauri\target\release\yaggui.exe` |
| SQLite database (repos, tabs, preferences) | `~/Library/Application Support/dev.tropico.yaggui/yaggui.db` | `%APPDATA%\dev.tropico.yaggui\yaggui.db` |

To start from scratch: quit yaggui and delete `yaggui.db`. For an isolated session that leaves the regular database alone: `YAGGUI_CONFIG_DIR=/an/empty/folder`. Detailed logs: `RUST_LOG=debug pnpm tauri dev`.

Prepare two or three test repositories: a clean one, one with uncommitted changes, one with an upstream (for ahead/behind), and a folder that is not a repository.

## 3. Checklist

Tick each item; "Expected" describes the correct behavior. OS-specific items are marked **(mac)** or **(win)**.

### Window and title bar

- [ ] **Startup without flash** — Expected: the window appears directly with the right theme, without a white frame or unstyled content.
- [ ] **Move the window** by dragging an empty area of the tab bar — Expected: the window follows; dragging a tab reorders it instead of moving the window.
- [ ] **Double-click** on an empty area of the bar — Expected: **(mac)** zoom (maximize/restore, per the "double-click a window's title bar" system setting); **(win)** maximize ↔ restore.
- [ ] **(mac)** Traffic lights — Expected: vertically centered in the 38 px bar and aligned with the tabs, without overlap. If they are off, note by how much (current `trafficLightPosition`: x 14, y 19, in `src-tauri/tauri.macos.conf.json`).
- [ ] **(mac)** Full screen (green light or ⌃⌘F) — Expected: the tab bar stays usable, the traffic lights disappear cleanly.
- [ ] **(win)** Minimize / Maximize / Close buttons on the right — Expected: they work; the Maximize icon becomes Restore when the window is maximized (including through Win+↑ or snapping).
- [ ] **(win)** Hovering the Maximize button — Expected: **no** Snap Layouts menu (known limit of windows without native decorations, accepted for M0). Win+Z and edge snapping (drag against an edge, Win+←/→) must work.
- [ ] **(win)** Resize by the edges and corners — Expected: possible on all four edges; the 900×560 minimum size is respected without clipped content.

### Tabs and shortcuts

(`⌘` on mac = `Ctrl` on Windows.)

- [ ] `⌘T` — Expected: new welcome tab (or focus on the search if the active tab already is a welcome tab).
- [ ] `⌘W` — Expected: closes the active **tab**, never the window; with a single tab, it is replaced by a welcome tab.
- [ ] `⌘1…8` / `⌘9` — Expected: activates tab n / the last tab.
- [ ] `⌃Tab` / `⌃⇧Tab` — Expected: next / previous tab.
- [ ] Dragging a tab — Expected: smooth reordering; the order is kept across restarts.
- [ ] Tab indicators — Expected: badge with the number of changes on a dirty repository, ⚠ during a rebase/merge.
- [ ] Switching tabs between 3 open repositories — Expected: instant (P-07, < 50 ms), each tab keeps its own panels and sizes.

### Opening a repository (F-001)

- [ ] Welcome → **Open** (or `⌘O`) — Expected: the OS's **native** folder picker, titled "Choose a repository folder", modal on the yaggui window. Picking a repository opens it in the welcome tab; from a repository tab, in a new tab.
- [ ] Picker → **Cancel** — Expected: nothing happens, no error.
- [ ] Picker → a **subfolder** of a repository — Expected: the root repository opens.
- [ ] Picker → a folder that **is not a repository** — Expected: error toast "… is not a Git repository".
- [ ] Welcome → **Enter a path…** — Expected: dialog with a field + a **Browse…** button (which opens the native picker, then opens the chosen folder). An invalid path shows the error in the dialog.
- [ ] **Drag & drop** a folder from the Finder / Explorer onto the window — Expected: drop overlay, then the repository opens.
- [ ] **CLI**: `pnpm tauri dev -- -- /path/to/repository` (or the release binary followed by the path) — Expected: the repository opens at startup.
- [ ] Opening a repository that is already open — Expected: its tab is activated, no duplicate.

### Repository state

- [ ] Dirty repository — Expected: right panel with the number of modified / untracked / staged files, badge on the tab.
- [ ] Branch with an upstream ahead/behind (local `git commit`, or `git reset --hard HEAD~1` after a fetch) — Expected: branch selector with ↑n / ↓n and the upstream name, counters on Pull / Push.
- [ ] Detached HEAD (`git checkout <sha>`) — Expected: selector showing "Detached HEAD" + short SHA.
- [ ] **Rebase in progress** (`git rebase -i HEAD~3` with an `edit`, or a conflicting rebase) — Expected: "Rebasing `<branch>` — step n / m" banner, ⚠ on the tab, conflicts counted.
- [ ] Orphan `index.lock` (create an empty `.git/index.lock`, wait 10 s) — Expected: banner with "Remove the lock…", a confirmation, then the banner disappears.

### Automatic refresh

- [ ] Edit / create a file in the repository with an external editor — Expected: counters updated in under a second, without any action.
- [ ] `git commit`, `git checkout -b x`, `git stash` in a terminal — Expected: branch and counters updated automatically.
- [ ] Edit `.git/config` (e.g. `git branch -u origin/main`) — Expected: the upstream is picked up.

### Command log (F-300) and errors (F-301)

- [ ] `⌘J` or "Log" in the status bar — Expected: resizable panel listing the git commands that ran (command, duration, code), "This repository / All" filter, expandable entries with stdout/stderr.
- [ ] Trigger an error (open a non-repository through "Enter a path…") — Expected: clear message in the UI language, collapsible technical details, suggested action when there is one.

### Themes and language

- [ ] Settings (⚙) → Light / Dark theme — Expected: immediate switch, Paper / Graphite correct everywhere (dialogs, menus, toasts, log).
- [ ] **System** theme, then change the OS appearance — Expected: yaggui follows live.
- [ ] Restart with each theme — Expected: no flash of the other theme at startup.
- [ ] Settings → Language Français / English / System — Expected: the whole UI changes, **(mac)** the app menu included; the preference is kept across restarts.

### Terminal (F-266)

- [ ] Repository toolbar → **Terminal** — Expected: **(mac)** Terminal.app opens in the repository folder; **(win)** Windows Terminal (`wt -d`) in the folder, or, without Windows Terminal, `cmd` in **its own console window**, which stays open and accepts input. `pwd` / `cd` confirms the folder.
- [ ] Repository path with spaces and accents — Expected: the terminal opens in the right folder.
- [ ] **(win)** Repository whose path contains a `;` (e.g. `C:\tmp\a;calc`, with `git init` inside) → Terminal — Expected: Windows Terminal opens in `C:\tmp\a;calc`; **no** calculator and no second tab.
- [ ] Settings → **Terminal…** → enter **(mac)** `iTerm` or `Warp` (if installed) **(win)** `powershell.exe`, then `pwsh`, then `wt` → Save, then Terminal — Expected: the chosen terminal opens **in the repository folder**; **(win)** PowerShell opens in its own console that stays open (no immediate exit, not sharing the `pnpm tauri dev` console); `wt` opens in the repository, not in `%USERPROFILE%`. The setting survives a restart.
- [ ] Enter a name that does not exist (`doesnotexist`), then Terminal — Expected: "Could not open a terminal" toast naming the culprit, with a **Choose a terminal…** action that reopens the setting. Clearing the field restores the default terminal.

### macOS menu **(mac)**

- [ ] Menu bar — Expected: yaggui, File, Edit, View, Window, Help (labels in the UI language).
- [ ] File → New Tab ⌘T / Open Repository… ⌘O / Close Tab ⌘W — Expected: same effects as the shortcuts, and the keyboard shortcut runs **only once** (a single tab created by ⌘T, a single one closed by ⌘W).
- [ ] Edit → Copy / Paste / Select All (and ⌘C / ⌘V / ⌘A / ⌘Z) in the welcome search and the path field — Expected: they work.
- [ ] View → left/right panels (⌥⌘B / ⌥⌘I), Command Log (⌘J), Full screen — Expected: they work.
- [ ] Window → Minimize (⌘M), Zoom, Show Next/Previous Tab — Expected: they work; the window list appears.
- [ ] yaggui → About, Hide (⌘H), Quit (⌘Q) — Expected: standard macOS behavior.
- [ ] With a dialog open (e.g. "Enter a path…"), ⌘W or ⌘T — Expected: no effect while the dialog is open.
- [ ] **(win)** — Expected: no menu bar.

### Restoring on restart

- [ ] Open 3 repositories, reorder them, resize the panels of one tab, activate the 2nd, quit (⌘Q / close), relaunch — Expected: same tabs, same order, same active tab, same panel sizes, repositories reopened and up to date.
- [ ] Rename/delete the folder of a restored repository, relaunch — Expected: the tab shows a clear error (folder not found) with a way to close the tab; the welcome screen marks it "Folder not found".

## 4. Performance measurements

Reproducible method, to run again on the reference machine:

```bash
pnpm tauri build --no-bundle
pnpm perf:startup        # P-01: 10 starts per scenario (headless Linux: xvfb-run -a pnpm perf:startup)
pnpm perf:tabs           # P-07: 60 tab switches, production build of the front on the mocked backend
```

- **P-01** (`scripts/measure-startup.mjs`): launches the release binary with `YAGGUI_PERF_PROBE=1`. The app only shows its window once the restored tabs have rendered; the probe records when the window becomes visible, then quits. Time is measured from the process `spawn` (executable loading, webview creation, JS boot, preferences, restore). Two scenarios: `welcome` (empty config) and `restore` (one restored repository tab). `--drop-caches` (Linux, root) drops the disk cache before each launch.
- **P-07** (`e2e/perf.spec.ts`, `playwright.perf.config.ts`): from the ⌃1/⌃2/⌃3 `keydown` to the next painted frame; checks that the right tab is shown. A tab switch calls no backend command (repository state is cached), so the measurement covers the whole visible cost. Measurement floor: one frame (~16.7 ms at 60 Hz). Also measured with a 4× CPU slowdown.

Results in the Linux CI container (xvfb, WebKitGTK 2.52, not a reference machine):

| Measure | Scenario | Median | Min – max | Target |
|---|---|---|---|---|
| P-01 start → interactive window | welcome, empty config (10 launches, disk cache dropped) | **680 ms** | 565 – 1,236 ms | < 800 ms ✅ |
| P-01 | 1 restored repository tab (10 launches) | **633 ms** | 588 – 1,712 ms | < 800 ms ✅ |
| P-07 tab switch (3 repositories, 60 switches) | production build | **17 ms** (p95 20 ms) | max 27 ms | < 50 ms ✅ |
| P-07 | 4× CPU slowdown | 69 ms (p95 123 ms) | max 133 ms | indicative |

The **first** launch after a build is slower (1.2 s welcome, 1.7 s restore): WebKitGTK creates its caches (`~/.cache/dev.tropico.yaggui`, fontconfig, shaders); later launches stay under 800 ms even with the disk cache dropped. To watch on macOS / Windows (WKWebView and WebView2 have their own first-launch cost). Within the P-01 time, ~100 ms happen before entering `run()` (loading the 24 MB binary and the GTK/WebKit libraries).

On macOS / Windows, include the output of `pnpm perf:startup` and `pnpm perf:tabs` in the report.

## 5. Reporting a problem

For each failing item, open an issue with:

1. **OS and version** (e.g. macOS 15.1 Apple Silicon, Windows 11 24H2), and mode (`pnpm tauri dev` or installed build).
2. **The checklist item** concerned (copy the line).
3. **Steps** to reproduce, from launch.
4. **Expected / actual**, one sentence each.
5. **Screenshot** (mac: ⌘⇧4; win: Win+⇧+S) or a short video for motion issues (drag, flash).
6. For an error: the error **details** ("Details" in the toast) and the **log** entry (⌘J, expand, "Copy"). For a crash: the terminal output of `pnpm tauri dev` (ideally with `RUST_LOG=debug`).
