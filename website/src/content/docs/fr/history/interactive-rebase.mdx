L’éditeur de rebase interactif réécrit les commits récents de la branche courante : vous les organisez dans une liste, vérifiez le résultat, et yaggui exécute `git rebase --interactive` à votre place, sans ouvrir d’éditeur de texte. Pour le côté Git, voir [Rewriting history](https://git-scm.com/book/en/v2/Git-Tools-Rewriting-History).

## Lancer un rebase interactif

Vous choisissez une **base** : le commit sur lequel les commits réécrits sont placés. La base elle-même n’est pas modifiée ; tous les commits qui la suivent, jusqu’à la pointe de la branche courante, sont listés (comme avec `git rebase -i <base>`).

- **Depuis un commit** : faites un clic droit sur un commit de la branche courante dans le graphe et choisissez **Rebase interactif depuis ici…**. Ce commit est la base.
- **Depuis la palette** : lancez **Rebase interactif depuis…** (<kbd>⌘K</kbd>, ou <kbd>Ctrl+K</kbd> sous Windows et Linux). Si un commit autre que HEAD est sélectionné dans le graphe, il sert de base. Sinon, un sélecteur demande « Rebaser au-dessus de quel commit ? Les commits qui le suivent seront listés. » et propose les 30 derniers commits de la branche (premiers parents uniquement), chacun avec **\{count\} commits au-dessus**. Utilisez <kbd>↑</kbd>/<kbd>↓</kbd> et <kbd>Enter</kbd>, ou cliquez sur l’un d’eux.

Pour fusionner des commits fixup dans les commits qu’ils corrigent, utilisez l’[Autosquash](#autosquash) : il ouvre le même éditeur avec la liste déjà arrangée.

L’éditeur remplace le graphe. Les deux points d’entrée sont désactivés tant qu’une autre opération est en cours.

L’éditeur refuse de démarrer, avec un message, dans les cas suivants :

| Message                                                                                                                                        | Cause                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| « HEAD est détaché (aucune branche courante) : fais d'abord un checkout d'une branche. »                                                       | Aucune branche n’est extraite                                                            |
| « \{short\} n'est pas un ancêtre de la branche courante. »                                                                                     | La base n’appartient pas à l’historique de la branche courante                           |
| « Plus de 200 commits à rebaser : choisis une base plus récente. »                                                                             | La plage est trop longue                                                                 |
| **Aucun commit après cette base : rien à rebaser.**                                                                                            | La base est la pointe de la branche                                                      |
| **Cette plage contient des commits de merge. yaggui ne reconstruit pas les merges dans un rebase interactif : choisis une base plus récente.** | Un commit de merge se trouve au-dessus de la base ; **Lancer le rebase** reste désactivé |

Vos modifications n’existent que dans l’éditeur ouvert : le quitter (**Annuler**, <kbd>Esc</kbd>) les abandonne, après la confirmation **Abandonner les modifications de la liste ?** dès que quelque chose a changé, et choisir une autre base repart de zéro.

## Modifier la liste

L’en-tête affiche la branche, **sur \{sha\} \{summary\}** et le nombre de commits. La liste **Commits à rebaser, du plus récent au plus ancien** place le commit le plus récent en haut, comme le graphe : « en dessous » signifie donc plus ancien. Chaque ligne affiche une poignée de glissement, le SHA, le résumé, l’auteur et la date, un badge **Poussé** quand le commit est déjà sur l’upstream (**Déjà sur \{target\}**), et les boutons d’action.

### Actions

Cliquez sur un bouton de la ligne, ou donnez le focus à la ligne et appuyez sur sa touche (sans modificateur) :

| Action     | Touche       | Effet                                                             |
| ---------- | ------------ | ----------------------------------------------------------------- |
| **Pick**   | <kbd>P</kbd> | Garder le commit tel quel                                         |
| **Reword** | <kbd>R</kbd> | Garder les changements, écrire un nouveau message                 |
| **Squash** | <kbd>S</kbd> | Fusionner dans le commit du dessous, en combinant les messages    |
| **Fixup**  | <kbd>F</kbd> | Fusionner dans le commit du dessous, en gardant son message       |
| **Drop**   | <kbd>D</kbd> | Supprimer le commit                                               |
| **Edit**   | <kbd>E</kbd> | S'arrêter après ce commit pour le modifier ou ajouter des commits |

Les lignes fusionnées affichent **Fusionné dans « \{summary\} »** ; une ligne **Edit** affiche **Le rebase s'arrête ici**.

### Réordonner

- Glissez une ligne par sa poignée et déposez-la au-dessus ou en dessous d’une autre ligne. La liste défile quand vous approchez de ses bords.
- Ou donnez le focus à une ligne et appuyez sur <kbd>⌥↑</kbd>/<kbd>⌥↓</kbd> (<kbd>Alt+↑</kbd>/<kbd>Alt+↓</kbd> sous Windows et Linux) pour la monter ou la descendre.

Autres touches dans la liste : <kbd>↑</kbd>/<kbd>↓</kbd> déplacent le focus, <kbd>Home</kbd>/<kbd>End</kbd> vont au commit le plus récent/le plus ancien, <kbd>Esc</kbd> annule un glissement ou quitte l’éditeur. Le pied de page rappelle ces touches.

### Modifier un message

Un commit reformulé (Reword), ou le dernier commit squashé (ou `fixup -C`) d’un groupe, porte le nouveau message. Cliquez sur **Modifier le message** sur cette ligne, ou donnez-lui le focus et appuyez sur <kbd>Enter</kbd>. Un éditeur en ligne s’ouvre avec un champ de résumé (doté d’un compteur `n/72`) et un champ de description.

- Le message par défaut est le message d’origine pour un Reword, et pour un groupe de squash le message que Git proposerait : le message du commit de tête suivi de chaque message squashé, sans la ligne de résumé `squash!` / `fixup!` / `amend!` que Git met en commentaire. Un Fixup garde le message du commit dans lequel il est fusionné ; un Fixup qui porte le message d’un commit `amend!` (`fixup -C`, voir [Autosquash](#autosquash)) le remplace, ou s’y ajoute après un squash.
- **Les lignes commençant par # sont conservées.**
- **Revenir au message par défaut** rétablit le message par défaut ; **Terminé**, <kbd>Esc</kbd> ou <kbd>⌘Enter</kbd> (<kbd>Ctrl+Enter</kbd> sous Windows et Linux) ferme l’éditeur.

### Validation

Les lignes qui posent problème sont mises en évidence et **Lancer le rebase** est désactivé avec **Corrige les commits signalés pour lancer** :

- **Rien en dessous où fusionner : garde un commit sous celui-ci** : un Squash ou un Fixup n’a aucun commit conservé en dessous.
- **Le message a besoin d'un résumé** : le message d’un Reword ou d’un Squash est vide.
- **Tous les commits sont supprimés : fais plutôt un reset de la branche.** (voir [Reset](../../history/cherry-pick-revert-reset/#reset-de-la-branche-courante)).

Quand rien n’a changé, l’indication est **Modifie au moins un commit pour lancer**.

### Aperçu du résultat

Le panneau **Résultat** montre les commits tels qu’ils seront après le rebase : **\{count\} commits**, **\{count\} commits supprimés**, et pour chaque commit des pastilles comme **\{count\} fusionnés**, **message modifié** ou **arrêt pour modification**. Son pied de page rappelle la base : **sur \{sha\} \{summary\}**.

Pour quitter sans rien faire, cliquez sur **Annuler** ou appuyez sur <kbd>Esc</kbd>. Dès que la liste diffère du plan (une action, l’ordre ou un message), yaggui demande d’abord **Abandonner les modifications de la liste ?** : **Abandonner** quitte l’éditeur, la branche intacte ; **Annuler** garde la liste telle quelle.

## Confirmer et lancer

Cliquez sur **Lancer le rebase**. La confirmation **Réécrire \{count\} commits de \{branch\} ?** compte les commits depuis le premier modifié jusqu’à la pointe, indique qu’ils « vont être réécrits et recevoir de nouveaux SHA », et affiche `git rebase -i <base>`.

Si certains commits réécrits sont déjà sur l’upstream, la confirmation se transforme en avertissement : « \{count\} des commits réécrits de \{branch\} sont déjà sur \{target\}. Après le rebase, \{branch\} diverge de \{target\} : seul un force push (--force-with-lease) pourra le mettre à jour. » Chacun de ces commits y est listé avec la mention **poussé sur \{target\}**. Voir [Force push](../../remotes/fetch-pull-push/).

Confirmez avec **Lancer le rebase**. yaggui :

1. Vérifie qu’aucune opération n’est en cours et qu’aucun fichier suivi n’a de modifications locales (« Tes modifications locales seraient écrasées par le rebase. Commite-les ou mets-les de côté (stash) d'abord. »).
2. Crée avec `git commit-tree` les commits qui portent un nouveau message (Reword et groupes de Squash), en conservant l’auteur et la date d’origine.
3. Écrit lui-même la liste todo (lignes `pick`, `fixup`, `edit`, `drop`) dans un dossier temporaire privé, supprimé ensuite.
4. Exécute `git rebase --interactive <base>` en remplaçant les éditeurs de Git, de sorte qu’aucun éditeur ne s’ouvre jamais.

La progression s’affiche dans la barre d’état. Une fois terminé : **Rebase de \{branch\} terminé**, et le graphe revient.

Si la branche a changé depuis le chargement de la liste, le rebase ne démarre pas (« La liste des commits ne correspond plus à la branche (elle a changé entre-temps) : recharge-la. ») et l’éditeur affiche **Le rebase n'a pas démarré** avec **Recharger les commits**.

## Quand le rebase s’arrête

### Sur un commit Edit

Un panneau **Rebase interrompu** affiche **Rebase arrêté à l'étape \{step\}/\{total\} sur \{sha\} \{summary\}** et « Modifie ce commit ou ajoute des commits par-dessus, puis continue. » HEAD est détaché pendant l’exécution du rebase. Modifiez le commit ou ajoutez-en depuis le panneau de commit (voir [Committer](../../everyday/committing/)), puis cliquez sur **Continuer**.

Le panneau propose **Continuer**, **Annuler le rebase** et **Fermer (le rebase reste en cours)**. Il n’y a pas de bouton **Passer** sur un arrêt d’édition.

### Sur des conflits

Le panneau affiche **Conflits à l'étape \{step\}/\{total\}**, « Résous les conflits dans le panneau des changements, puis continue. » et **\{count\} fichiers encore en conflit**. L’éditeur de merge s’ouvre sur le premier fichier en conflit ; le bouton **Graphe** de sa barre d’outils ramène au panneau. Quand tous les fichiers sont résolus, le panneau affiche **Tous les conflits sont résolus.** et **Continuer** devient disponible. **Passer** abandonne le commit en cours. Voir [Résoudre les conflits](../../history/conflicts/).

Après **Continuer** ou **Passer**, le panneau suit l’arrêt suivant, ou se ferme quand le rebase est terminé. Vous pouvez aussi continuer ou annuler depuis le [bandeau d’opération](../../history/conflicts/#le-bandeau-dopération-en-cours) au-dessus du graphe ; l’éditeur se ferme de lui-même dès que le rebase n’est plus en cours.

:::caution
**Annuler le rebase** dans ce panneau exécute `git rebase --abort` sans demander de confirmation (le bouton **Annuler le rebase** du bandeau, lui, en demande une). La branche revient à son état d’avant le rebase. Notification : **Rebase de \{branch\} abandonné**.
:::

## Commits fixup et autosquash

Un commit fixup porte une correction pour un commit plus ancien de la branche, à fusionner dedans plus tard.

### Créer un fixup

Stagez la correction, puis faites un clic droit sur le commit qu’elle corrige dans le graphe et choisissez **Créer un fixup pour ce commit**, ou sélectionnez ce commit et lancez **Créer un fixup pour le commit sélectionné** depuis la palette. yaggui commite les modifications stagées avec `git commit --fixup=<sha>` : le message est `fixup! ` suivi du résumé de ce commit (`fixup! fixup! …` pour un fixup d’un fixup). Les hooks s’exécutent comme pour tout commit ; un refus affiche leur sortie dans le panneau de commit.

Le toast indique **Fixup \{sha\} créé pour \{target\}**, avec un bouton **Autosquash**. Comme un commit, le fixup s’annule avec <kbd>⌘Z</kbd> (<kbd>Ctrl+Z</kbd> sous Windows et Linux) : voir [Annuler et rétablir](../../history/undo-and-redo/).

L’entrée est désactivée, avec la raison, quand rien n’est stagé (**Stage d'abord les modifications du fixup**), quand le dépôt n’a pas encore de commit (**Pas encore de commit**) ou pendant une opération. Un commit qui n’est pas sur la branche courante est refusé : « Ce commit n'est pas sur la branche courante : bascule sur sa branche pour lui créer un fixup. »

### Autosquash

**Autosquash** ouvre l’éditeur de rebase interactif avec chaque commit `fixup!`, `squash!` et `amend!` déjà placé juste au-dessus du commit qu’il vise, pour que vous relisiez la liste avant de la lancer. Rien n’est réécrit avant que vous cliquiez sur **Lancer le rebase**. Il est proposé :

- dans la palette : **Autosquash des fixups…** ;
- dans le menu d’un commit `fixup!`, `squash!` ou `amend!` du graphe : **Autosquash des fixups…** ;
- par le bouton **Autosquash** du toast après la création d’un fixup ;
- par le bouton **Autosquash** de l’en-tête de l’éditeur, quand la liste contient de tels commits. Il arrange à nouveau la liste depuis la même base ; vos modifications sont remplacées.

Depuis la palette, le menu et le toast, la base est le parent du plus ancien commit visé par l’un d’eux, cherché parmi les derniers commits de la branche : premiers parents depuis la pointe, jusqu’au premier commit de merge, 200 commits au plus. Quand aucun n’y a de cible, un toast indique **Aucun commit fixup!, squash! ou amend! à fusionner sur cette branche**. L’en-tête affiche **\{count\} commits placés sous leurs cibles**.

Chaque commit reçoit l’action que lui donnerait `git rebase --autosquash`, d’après son premier préfixe :

| Le résumé commence par | Action                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fixup! `              | **Fixup** : fusionné, la cible garde son message.                                                                                                                                                                       |
| `squash! `             | **Squash** : fusionné, les messages sont combinés (sans sa ligne `squash!`).                                                                                                                                            |
| `amend! `              | **Fixup** avec le message de ce commit (le `fixup -C` de Git) : la ligne indique « Fusionné dans « \{summary\} », avec le message de ce commit (fixup -C) », et la cible prend le message situé sous la ligne `amend!`. |

Ils sont associés comme avec `git rebase --autosquash` :

- tous les préfixes `fixup! `, `squash! ` et `amend! ` sont retirés du résumé, mélangés ou répétés (`fixup! squash! Add x` vise `Add x`) ; un préfixe doit être suivi de son espace ;
- la cible est le plus ancien commit en dessous ayant exactement ce résumé, parmi ceux qui restent en place ; sinon, pour un résumé sans espace, le commit en dessous qu’il désigne (un SHA de 4 caractères ou plus, une branche, un tag) ; sinon le plus ancien commit en dessous dont le résumé commence par lui ;
- les commits d’une même cible gardent leur ordre sous elle, et un commit qui vise un commit déjà déplacé (`fixup! <sha d’un fixup>`) se place juste après lui.

Un commit dont la cible n’est pas dans la liste (la cible est la base ou plus ancienne, ou rien ne correspond) reste à sa place, en **Pick**, avec **Aucun commit de la liste ne correspond à ce fixup : il reste à sa place**. Un commit `amend!` sans rien sous sa ligne `amend!` laisserait un message vide : la ligne est signalée et le rebase ne peut pas démarrer avant que vous en écriviez un.

Le reste est l’éditeur habituel : modifiez ce que vous voulez, puis [confirmez et lancez](#confirmer-et-lancer). Un rebase qui réécrit des commits poussés demande un force push, et le rebase lui-même ne s’annule pas.

## Modifier le message d’un seul commit

Pour changer seulement le message d’un commit, sans ouvrir l’éditeur, faites un clic droit sur le commit dans le graphe et choisissez **Modifier le message du commit…**. La boîte de dialogue **Modifier le message de _abc1234_** affiche le message complet (résumé, ligne vide, corps) ; modifiez-le, puis cliquez sur **Modifier le message** ou appuyez sur <kbd>⌘↵</kbd> / <kbd>Ctrl+↵</kbd>. Le bouton reste désactivé tant que le message est inchangé ou que sa première ligne est vide.

Vous pouvez aussi le modifier sur place depuis le panneau **Détail du commit** : sélectionnez le commit, puis cliquez sur son message, ou sur le crayon qui apparaît au survol (**Modifier le message du commit**). L’en-tête devient un champ **Résumé du commit** avec un compteur de caractères (_n_/72), un champ **Description (facultative)** et la même explication que la boîte de dialogue. Cliquez sur **Modifier le message** ou appuyez sur <kbd>⌘↵</kbd> / <kbd>Ctrl+↵</kbd> ; <kbd>Esc</kbd> ou **Annuler** abandonne la modification. Sélectionner du texte du message pour le copier ne lance pas l’édition. Une fois le message modifié, le graphe sélectionne le commit réécrit. Le crayon est désactivé pendant une opération en cours ; si la modification échoue, le message saisi reste dans les champs.

| Commit                                       | Ce que fait yaggui                                                                                                                                                                                                                                                                                            | Commande                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Le dernier commit (HEAD)                     | L’amende avec le nouveau message. Les modifications stagées n’y sont pas ajoutées, et la copie de travail peut contenir des modifications. Annulable comme un amend.                                                                                                                                          | `git commit --amend --only --allow-empty --no-verify --cleanup=verbatim` |
| Un commit plus ancien de la branche courante | Lance un rebase interactif depuis son parent : ce commit est reformulé, les commits qui le suivent sont rejoués à l’identique et reçoivent de nouveaux SHA. Mêmes règles qu’un rebase : pas de modification locale de fichiers suivis, pas de merge après le commit, pas d’opération en cours. Non annulable. | `git rebase --interactive <parent>`                                      |

Le message est gardé tel quel (lignes commençant par `#` comprises). Les hooks `pre-commit` et `commit-msg` ne s’exécutent pas, puisque le contenu ne change pas. Si les commits réécrits étaient déjà poussés, le prochain push demandera un force push.

La notification indique « Message modifié (_abc1234_) », avec le nouveau SHA. Erreurs :

- « Ce commit n'est pas sur la branche courante : bascule sur sa branche pour modifier son message. »
- « Le premier commit du dépôt ne peut être reformulé que lorsqu'il est HEAD. »
- « Ce commit vient d'un merge : yaggui ne peut pas le réécrire. »

## Annulation

Un rebase interactif n’est pas enregistré dans l’historique d’annulation : <kbd>⌘Z</kbd> ne l’annule pas. Tant qu’il est en cours, **Annuler le rebase** restaure la branche. Une fois terminé, retrouvez l’ancienne pointe dans le [reflog](../../inspect/reflog/) et resetez-y la branche. Voir [Annuler et rétablir](../../history/undo-and-redo/).
