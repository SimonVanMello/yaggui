Quand quelque chose échoue, yaggui affiche un message écrit pour les humains, pas la sortie brute de Git, et propose la suite sous forme de bouton quand il y en a une. Cette page explique où les erreurs apparaissent, puis liste chaque message par domaine pour que vous puissiez rechercher le texte que vous voyez.

## Comment les erreurs s’affichent

  dark={errorToastRetryDark}
  light={errorToastRetryLight}

/>

- **Toast** : la plupart des erreurs apparaissent sous forme de toast en bas à droite. Les toasts d’erreur restent jusqu’à ce que vous les fermiez (le bouton **×**, ou en les faisant glisser vers la droite). Les avertissements, comme un merge arrêté sur des conflits, se ferment tout seuls au bout de quelques secondes. Le toast d’une opération échouée porte son nom, par exemple « Fetch a échoué » ou « Push a échoué », avec le message en dessous.
- **Panneau intégré** : quand l’erreur concerne une boîte de dialogue ou un panneau, elle s’affiche à l’intérieur, et la boîte de dialogue reste ouverte pour que vous puissiez corriger la saisie. Exemples : la boîte de dialogue **Ouvrir un dépôt**, un onglet de dépôt qui n’a pas pu s’ouvrir (« Impossible d'ouvrir le dépôt », « Impossible d'ouvrir \{name\} »), la zone de commit.
- **Bannière** : certains états s’affichent plutôt dans une bannière au-dessus du graphe : un fichier de verrou Git, le rafraîchissement automatique indisponible, une opération en cours (voir [Conflits](../../history/conflicts/)).
- **Boîte de dialogue** : quelques erreurs ouvrent une boîte de dialogue dédiée, par exemple des modifications locales qui gênent un checkout, ou une annulation qui écraserait des modifications locales.

Chaque erreur peut comporter :

- **Détails** : une section repliée avec le texte technique brut, en général ce que Git a écrit sur stderr. Dépliez-la pour lire les mots exacts de Git ; sélectionnez le texte pour le copier.
- **Un bouton d'action** : la correction que yaggui peut lancer à votre place. Les libellés sont listés ci-dessous.

Une erreur qui n’est pas une erreur typée de yaggui (un bogue de l’interface) affiche un toast intitulé « Une erreur inattendue s'est produite », avec le texte technique sous **Détails**. [Signalez-la](../../help/troubleshooting/#signaler-un-bug), s’il vous plaît.

### Boutons d’action

| Bouton                          | Ce qu’il fait                                                                                                                                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Réessayer**                   | Relance l’action qui a échoué.                                                                                                                                                                                   |
| **Rafraîchir**                  | Recharge les données (liste des fichiers, diff, branches) et relance l’action.                                                                                                                                   |
| **Ouvrir le journal**           | Ouvre le [journal des commandes](../../reference/command-log/), passe son filtre sur **Toutes** si besoin, puis déplie et met en évidence la dernière commande en échec avec sa sortie complète.                 |
| **Faire confiance au dossier…** | Demande confirmation, puis exécute `git config --global --add safe.directory <path>` et rouvre le dépôt. Voir [Le dépôt ne s’ouvre pas](../../help/troubleshooting/#le-dépôt-appartient-à-un-autre-utilisateur). |
| **Supprimer le verrou…**        | Demande confirmation, puis supprime l'`index.lock` périmé. Voir [Un autre processus Git utilise ce dépôt](../../help/troubleshooting/#un-autre-processus-git-utilise-ce-dépôt).                                  |
| **Installer Git**               | Explique comment installer Git 2.30 ou plus récent.                                                                                                                                                              |
| **Renseigner mon identité**     | Ouvre le formulaire d’identité dans la zone de commit.                                                                                                                                                           |
| **Choisir un terminal…**        | Ouvre le réglage du terminal.                                                                                                                                                                                    |
| **Pull puis push**              | Fait un pull avec votre stratégie par défaut, puis pousse de nouveau.                                                                                                                                            |
| **Créer l'upstream et pousser** | Pousse de nouveau et crée l’upstream, après confirmation.                                                                                                                                                        |

Un bouton n’apparaît que s’il a du sens là où l’erreur s’est produite : par exemple **Réessayer** a besoin d’une action à répéter.

## Lire le catalogue

Les tableaux ci-dessous listent chaque message tel que yaggui l’affiche en français. Les parties entre accolades sont remplacées par la valeur concernée : `{path}` est un chemin de dossier ou de fichier, `{name}` un nom de branche, de tag ou de remote, `{short}` un hash de commit de 7 caractères. L’interface anglaise affiche les mêmes messages en anglais. La dernière colonne donne le code d’erreur interne, que vous pouvez citer dans un rapport de bogue.

yaggui reconnaît les erreurs propres à Git d’après leur texte anglais (il lance Git avec `LC_ALL=C`), donc la reconnaissance fonctionne quelle que soit la langue de votre système. Un échec de Git qui ne correspond à rien dans le catalogue affiche « La commande Git a échoué. » avec la sortie de Git sous **Détails**.
