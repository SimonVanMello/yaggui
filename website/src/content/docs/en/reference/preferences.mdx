This page lists every setting of the **Preferences** dialog, section by section, in the order of its sidebar. Each row links to the page that explains the feature.

## Open the preferences

- The gear button (**Preferences**) in the title bar.
- <kbd>⌘,</kbd> (<kbd>Ctrl+,</kbd> on Windows and Linux), rebindable.
- **Open preferences** in the [command palette](../../customize/palette-and-shortcuts/).
- On macOS, **yaggui › Preferences…**.
- **Edit shortcuts…** in the keyboard shortcuts sheet opens it on the **Shortcuts** section.

The dialog opens on **General**. The sidebar on the left lists eight sections in two groups:

| Group           | Sections                                                           |
| --------------- | ------------------------------------------------------------------ |
| **Application** | **General**, **Appearance**, **Display**, **Shortcuts**, **Tools** |
| **Git**         | **Fetch and pull**, **Safety**, **Git configuration**              |

Changes apply immediately: there is no Save or Cancel button. Text fields save when you press <kbd>Enter</kbd> or leave the field. If yaggui refuses a value, the setting goes back to its previous value and a toast "Could not save the preference" explains why. Close the dialog with the **×** in its header or <kbd>Esc</kbd>. <kbd>Esc</kbd> first cancels a shortcut capture, ends a theme preview, or clears the search when the search field has the focus.

## Search the settings

The **Search settings** field ("Search…") at the top of the sidebar searches every section at once. <kbd>⌘F</kbd> (<kbd>Ctrl+F</kbd> on Windows and Linux) puts the focus in it, and <kbd>Esc</kbd> in the field clears it.

- It matches the labels and hints of the settings in English and in French, ignoring accents and case, plus extra keywords and Git keys such as `pull.rebase` or `user.email`. Every word you type must match.
- It also finds color themes by name and commands by title: the matching section then shows the theme gallery or the shortcut list already filtered.
- The pane shows **Results** and a count ("4 settings for "pull""): the matching settings of every section, each group under the path of its section (for example "Git › Fetch and pull") with an **Open the section** button, which opens that section on the first match.
- In the sidebar, each section shows its number of matches, and sections without a match are greyed out.
- When nothing matches: "No setting matches "_query_". Try an English word or a Git key such as pull.rebase."

## Fetch and pull

See [Fetch, pull and push](../../remotes/fetch-pull-push/).

| Label                        | Values                                                              | Default               | Effect                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fetch automatically**      | On, off                                                             | On                    | Fetches all remotes of every open repository in the background, the repositories of the other tabs included. Skipped while an operation runs in that repository, and silent: no toast                                                                                                                                                        |
| **Every (minutes)**          | 1 to 240                                                            | 10                    | Interval of the automatic fetch. Disabled when automatic fetch is off. Out-of-range values are clamped                                                                                                                                                                                                                                       |
| **Prune on fetch**           | On, off                                                             | On                    | Adds `--prune` to every fetch: remote-tracking branches deleted on the remote are removed                                                                                                                                                                                                                                                    |
| **Show tags on the remotes** | On, off                                                             | Off                   | Adds a cloud to the labels of the tags a remote holds at the same commit. Lists the tags of every remote with `git ls-remote --tags` when turned on, when a repository opens and after each fetch, pull and push. **Learn more** under the switch explains how it works. See [Commit graph](../../history/commit-graph/#tags-on-the-remotes) |
| **Default pull strategy**    | **Git configuration**, **Fast-forward only**, **Merge**, **Rebase** | **Git configuration** | Used when you pull without choosing. **Git configuration** follows `branch.<name>.rebase`, `pull.rebase` and `pull.ff`, and falls back to fast-forward only                                                                                                                                                                                  |

## Safety

| Label                  | Values                                       | Default                                  | Effect                                                                                                                                                                                                                          |
| ---------------------- | -------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Protected branches** | Branch names or patterns such as `release/*` | `main`, `master`, `develop`, `release/*` | Force push to them and deleting them on the remote are refused, and branch cleanup never lists them. **Restore defaults** brings the default list back. An empty list protects nothing. See [Branches](../../history/branches/) |
| **Confirmations**      | One switch per confirmation                  | All on                                   | See [below](#confirmations-you-can-turn-off)                                                                                                                                                                                    |

Only a trailing `/*` is a wildcard: `release/*` matches `release/1.0` and `release/a/b`, but not `release` itself. Any other entry must match the branch name exactly. Entries cannot contain spaces, and up to 100 are allowed.

### Confirmations you can turn off

The **Confirmations** group of the **Safety** section ("Ask before these actions. The dialog always shows what will happen.") has four switches:

| Switch              | Confirmation it controls                                                   | Can be turned off                                   |
| ------------------- | -------------------------------------------------------------------------- | --------------------------------------------------- |
| **Discard changes** | "Discard all unstaged changes?", discarding selected files, hunks or lines | Yes                                                 |
| **Delete a tag**    | "Delete the tag _name_?"                                                   | Yes                                                 |
| **Drop a stash**    | "Drop this stash?"                                                         | Yes                                                 |
| **Force push**      | "Overwrite _branch_?"                                                      | No: "Always asked: it rewrites the remote history." |

A turned-off confirmation runs the action at once. Other confirmations are always shown and have no switch, for example: rebase ("Rebase _branch_ onto _target_?"), rewriting commits in an interactive rebase, aborting an operation, deleting a remote branch or tag, removing a remote, publishing a branch, deleting a workspace, undo when local changes are in the way, trusting a folder (`safe.directory`) and removing an index lock. Reset and branch deletion use their own dialogs.

The palette commands **Theme: follow the system**, **Theme: light** and **Theme: dark** change the same light / dark mode as the **Follow the system theme** switch. **Theme: choose a color theme…** lists the color themes in the palette (<kbd>↑</kbd> <kbd>↓</kbd> to preview) and applies the one you pick, like the gallery of the **Appearance** section.

## Where preferences are stored

Preferences are not in a `settings.json` file. They are stored in the SQLite database `yaggui.db`, in the `preferences` table (one row per setting, JSON values), in yaggui's configuration folder:

| OS      | Configuration folder                                                      |
| ------- | ------------------------------------------------------------------------- |
| Linux   | `~/.config/dev.tropico.yaggui` (or `$XDG_CONFIG_HOME/dev.tropico.yaggui`) |
| macOS   | `~/Library/Application Support/dev.tropico.yaggui`                        |
| Windows | `%APPDATA%\dev.tropico.yaggui`                                            |

The `YAGGUI_CONFIG_DIR` environment variable replaces this folder.

- Shortcuts are stored separately in `keybindings.json`, in the same folder, which you can edit by hand. See [Edit keybindings.json](../../customize/palette-and-shortcuts/#edit-keybindingsjson).
- Avatars are cached in the OS cache folder, not with the preferences.
- An unreadable or out-of-range value falls back to its default. If the database cannot be opened, yaggui starts with the defaults and keeps changes in memory only: they are lost when you quit.
- To reset every preference, quit yaggui and delete `yaggui.db`. This also forgets your repositories, tabs and workspaces. See [Data and privacy](../../reference/data-and-privacy/).

## Import and export

To carry your preferences and shortcuts to another machine by hand, use **Export…** and **Import…** in **Preferences › General**, under **Backup** (row **Import or export the preferences**). The same two commands are in the command palette: **Export preferences and shortcuts…** and **Import preferences and shortcuts…**.

**Export…** asks where to save a file (`yaggui-preferences.json` by default) and writes your current preferences and custom shortcuts to it. The toast "Preferences and shortcuts exported" shows the path.

**Import…** asks for a file and opens **Import preferences**, which lists what would change before anything is applied: each preference with its current and new value, each shortcut with its current and new binding, and what is left out. Nothing is written until you click **Import**, which applies everything in one step. If the file would change nothing, the dialog says so and **Import** stays disabled.

### What the file holds

```json
{
  "format": "yaggui-preferences",
  "version": 1,
  "preferences": { "theme": "dark", "fontSize": 14 },
  "keybindings": [{ "action": "tab.new", "shortcut": "Mod+N" }]
}
```

- **Exported preferences:** light / dark mode, light theme, dark theme, interface style, language, what the Terminal button opens, diff layout and options, high contrast, density, interface and code fonts, text size, automatic fetch and its interval, prune on fetch, default pull strategy, protected branches, turned-off confirmations, Gravatar avatars and tags on the remotes.
- **Never exported (specific to a machine):** the Git binary path, the editor, the external terminal, the diff and merge tools, and the answer to the update check question. Their paths and programs differ from one install to the next, and the update check is an opt-in you answer on each machine. If a file contains them anyway, they are ignored and listed under **Left out**, and the values on this machine stay as they are.
- **Shortcuts:** the list in `keybindings` is your whole set of custom shortcuts. Importing it **replaces** the custom shortcuts of this machine: a command the file does not list goes back to its default shortcut. The preview shows each change.
- **Preferences missing from the file** keep their value on this machine. **Unknown keys** (a setting added by a newer yaggui, or a typo) are ignored and listed.
- Identity profiles, commit templates, repositories, tabs and workspaces are not preferences and are never exported.

### Files yaggui refuses

A file that is not valid JSON, is not a yaggui preferences file, holds a value out of range or of the wrong type (for example `"fontSize": 99`), or has an invalid shortcut is refused as a whole: nothing is changed and a toast "Could not import the file" explains why, with the keys at fault under **Details**. A file whose `version` is higher than the one this yaggui reads is refused with a message asking you to update yaggui. See [Error messages](../../reference/error-messages/).
