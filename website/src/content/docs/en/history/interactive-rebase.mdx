The interactive rebase editor rewrites the recent commits of the current branch: you arrange them in a list, check the result, and yaggui runs `git rebase --interactive` for you without opening a text editor. For the Git side, see [Rewriting history](https://git-scm.com/book/en/v2/Git-Tools-Rewriting-History).

## Start an interactive rebase

You choose a **base**: the commit the rewritten commits are placed on. The base itself is not changed; every commit above it, up to the tip of the current branch, is listed (like `git rebase -i <base>`).

- **From a commit**: right-click a commit of the current branch in the graph and choose **Interactive rebase from here…**. That commit is the base.
- **From the palette**: run **Interactive rebase from…** (<kbd>⌘K</kbd>, or <kbd>Ctrl+K</kbd> on Windows and Linux). If a commit other than HEAD is selected in the graph, it is the base. Otherwise a picker asks "Rebase on top of which commit? The commits above it will be listed." and lists the 30 latest commits of the branch (first parents only), each with **\{count\} commits above**. Use <kbd>↑</kbd>/<kbd>↓</kbd> and <kbd>Enter</kbd>, or click one.

To meld fixup commits into the commits they fix, use [Autosquash](#autosquash): it opens the same editor with the list already arranged.

The editor replaces the graph. Both entry points are disabled while another operation is in progress.

The editor refuses to start, with a message, when:

| Message                                                                                                                    | Cause                                                             |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| "HEAD is detached (no current branch): check out a branch first."                                                          | No branch is checked out                                          |
| "\{short\} is not an ancestor of the current branch."                                                                      | The base is not in the history of the current branch              |
| "More than 200 commits to rebase: choose a more recent base."                                                              | The range is too long                                             |
| **There is no commit after this base: nothing to rebase.**                                                                 | The base is the tip of the branch                                 |
| **This range contains merge commits. yaggui does not rebuild merges in an interactive rebase: choose a more recent base.** | A merge commit is above the base; **Start rebase** stays disabled |

Your edits live only in the open editor: leaving it (**Cancel**, <kbd>Esc</kbd>) discards them, and choosing another base starts over.

The header shows the branch, **onto \{sha\} \{summary\}** and the number of commits. The list **Commits to rebase, newest first** has the newest commit on top, like the graph, so "below" means older. Each row shows a drag grip, the SHA, summary, author and date, a **Pushed** badge when the commit is already on the upstream (**Already on \{target\}**), and the action buttons.

### Actions

Click a button on the row, or focus the row and press its key (no modifier):

| Action     | Key          | Effect                                             |
| ---------- | ------------ | -------------------------------------------------- |
| **Pick**   | <kbd>P</kbd> | Keep the commit as it is                           |
| **Reword** | <kbd>R</kbd> | Keep the changes, write a new message              |
| **Squash** | <kbd>S</kbd> | Meld into the commit below, combining the messages |
| **Fixup**  | <kbd>F</kbd> | Meld into the commit below, keeping its message    |
| **Drop**   | <kbd>D</kbd> | Remove the commit                                  |
| **Edit**   | <kbd>E</kbd> | Stop after this commit to amend it or add commits  |

Rows that are melded show **Melded into "\{summary\}"**; an **Edit** row shows **The rebase stops here**.

### Reorder

- Drag a row by its grip and drop it above or below another row. The list scrolls when you approach its edges.
- Or focus a row and press <kbd>⌥↑</kbd>/<kbd>⌥↓</kbd> (<kbd>Alt+↑</kbd>/<kbd>Alt+↓</kbd> on Windows and Linux) to move it up or down.

Other keys in the list: <kbd>↑</kbd>/<kbd>↓</kbd> move the focus, <kbd>Home</kbd>/<kbd>End</kbd> go to the newest/oldest commit, <kbd>Esc</kbd> cancels a drag or leaves the editor. The footer recalls these keys.

### Edit a message

A reworded commit, or the last squashed commit (or `fixup -C`) of a group, carries the new message. Click **Edit message** on that row, or focus it and press <kbd>Enter</kbd>. An inline editor opens with a summary field (with a `n/72` counter) and a description field.

- The default message is the original message for a reword, and for a squash group the message Git would propose: the head message followed by each squashed message, without the `squash!` / `fixup!` / `amend!` summary line Git comments out. A fixup keeps the message of the commit it melds into; a fixup with the message of an `amend!` commit (`fixup -C`, see [Autosquash](#autosquash)) replaces it, or adds to it after a squash.
- **Lines starting with # are kept.**
- **Use the default message** restores the default; **Done**, <kbd>Esc</kbd> or <kbd>⌘Enter</kbd> (<kbd>Ctrl+Enter</kbd> on Windows and Linux) closes the editor.

### Validation

Rows with a problem are highlighted and **Start rebase** is disabled with **Fix the highlighted commits to start**:

- **Nothing below to meld into: keep a commit below it**: a squash or fixup has no kept commit below it.
- **The message needs a summary**: a reword or squash message is empty.
- **Every commit is dropped: reset the branch instead.** (see [Reset](../../history/cherry-pick-revert-reset/#reset-the-current-branch)).

When nothing changed, the hint is **Change at least one commit to start**.

### Result preview

The **Result** panel shows the commits as they will be after the rebase: **\{count\} commits**, **\{count\} commits dropped**, and for each commit chips such as **\{count\} melded**, **edited message** or **stops for editing**. Its footer recalls the base: **on top of \{sha\} \{summary\}**.

To leave without doing anything, click **Cancel** or press <kbd>Esc</kbd>.

## Confirm and run

Click **Start rebase**. The confirmation **Rewrite \{count\} commits of \{branch\}?** counts the commits from the first changed one to the tip, says they "will be rewritten and get new SHAs", and shows `git rebase -i <base>`.

If some rewritten commits are already on the upstream, the confirmation turns into a warning: "\{count\} of the rewritten commits of \{branch\} are already on \{target\}. Once rebased, \{branch\} diverges from \{target\} and only a force push (--force-with-lease) can update it." It lists each of those commits as **pushed to \{target\}**. See [Force push](../../remotes/fetch-pull-push/).

Confirm with **Start rebase**. yaggui:

1. Checks that no operation is in progress and no tracked file has local changes ("Your local changes would be overwritten by the rebase. Commit or stash them first.").
2. Creates the commits that carry a new message (rewords and squash groups) with `git commit-tree`, keeping the original author and date.
3. Writes the todo list itself (`pick`, `fixup`, `edit`, `drop` lines) to a private temporary folder, deleted afterwards.
4. Runs `git rebase --interactive <base>` with Git's editors replaced, so no editor ever opens.

Progress shows in the status bar. When it completes: **Rebase of \{branch\} completed**, and the graph comes back.

If the branch changed since the list was loaded, the rebase does not start ("The list of commits no longer matches the branch (it changed meanwhile): reload it.") and the editor shows **The rebase did not start** with **Reload the commits**.

## When the rebase stops

### On an Edit commit

A **Rebase stopped** panel shows **Rebase stopped at step \{step\}/\{total\} on \{sha\} \{summary\}** and "Amend this commit or add commits on top of it, then continue." HEAD is detached while the rebase runs. Amend the commit or add new ones from the commit panel (see [Committing](../../everyday/committing/)), then click **Continue**.

The panel has **Continue**, **Abort rebase** and **Close (the rebase stays in progress)**. There is no **Skip** on an edit stop.

### On conflicts

The panel shows **Conflicts at step \{step\}/\{total\}**, "Resolve the conflicts in the changes panel, then continue." and **\{count\} files still in conflict**. The merge editor opens on the first conflicted file; **Graph** in its toolbar goes back to the panel. When every file is resolved, the panel says **All conflicts are resolved.** and **Continue** becomes available. **Skip** drops the current commit. See [Resolve conflicts](../../history/conflicts/).

After **Continue** or **Skip**, the panel follows the next stop, or closes when the rebase is done. You can also continue or abort from the [operation banner](../../history/conflicts/#the-operation-in-progress-banner) above the graph; the editor closes by itself once the rebase is no longer in progress.

:::caution
**Abort rebase** in this panel runs `git rebase --abort` without asking for confirmation (the banner's **Abort rebase** asks). The branch goes back to how it was before the rebase. Toast: **Rebase of \{branch\} aborted**.
:::

## Fixup commits and autosquash

A fixup commit carries a correction for an older commit of the branch, to be melded into it later.

### Create a fixup

Stage the correction, then right-click the commit it fixes in the graph and choose **Create a fixup for this commit**, or select that commit and run **Create a fixup for the selected commit** from the palette. yaggui commits the staged changes with `git commit --fixup=<sha>`: the message is `fixup! ` followed by the summary of that commit (`fixup! fixup! …` for a fixup of a fixup). Hooks run as for any commit; a rejection shows its output in the commit panel.

The toast reads **Fixup \{sha\} created for \{target\}**, with an **Autosquash** button. Like a commit, the fixup is undoable with <kbd>⌘Z</kbd> (<kbd>Ctrl+Z</kbd> on Windows and Linux): see [Undo and redo](../../history/undo-and-redo/).

The entry is disabled, with the reason, when nothing is staged (**Stage the changes of the fixup first**), when the repository has no commit yet (**No commit yet**) or while an operation is in progress. A commit that is not on the current branch is refused: "This commit is not on the current branch: check out its branch to create a fixup for it."

### Autosquash

**Autosquash** opens the interactive rebase editor with each `fixup!`, `squash!` and `amend!` commit already moved right above the commit it targets, so you review the list before running it. Nothing is rewritten until you click **Start rebase**. It is offered:

- in the palette: **Autosquash the fixups…**;
- in the menu of a `fixup!`, `squash!` or `amend!` commit in the graph: **Autosquash the fixups…**;
- as the **Autosquash** button of the toast after creating a fixup;
- as the **Autosquash** button of the editor header, when the list contains such commits. It arranges the list again from the same base; your edits are replaced.

From the palette, the menu and the toast, the base is the parent of the oldest commit one of them targets, looked for among the latest commits of the branch: first parents from the tip, up to the first merge commit, 200 commits at most. When none has a target there, a toast says **No fixup!, squash! or amend! commit to squash on this branch**. The header shows **\{count\} commits moved under their targets**.

Each commit gets the action `git rebase --autosquash` would give it, from its first prefix:

| Summary starts with | Action                                                                                                                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fixup! `           | **Fixup**: melded in, the target keeps its message.                                                                                                                                                  |
| `squash! `          | **Squash**: melded in, the messages are combined (its `squash!` line left out).                                                                                                                      |
| `amend! `           | **Fixup** with this commit's message (Git's `fixup -C`): the row reads "Melded into “\{summary\}”, with this commit’s message (fixup -C)", and the target takes the message below the `amend!` line. |

They are matched like `git rebase --autosquash`:

- every `fixup! `, `squash! ` and `amend! ` prefix is removed from the summary, mixed or repeated (`fixup! squash! Add x` targets `Add x`); a prefix needs its space;
- the target is the oldest commit below with exactly that summary, among those left in place; otherwise, for a summary without spaces, the commit below it names (a SHA of 4 characters or more, a branch, a tag); otherwise the oldest commit below whose summary starts with it;
- the commits of the same target keep their order under it, and one that targets a commit already moved (`fixup! <sha of a fixup>`) goes right after that commit.

A commit whose target is not in the list (the target is the base or older, or nothing matches) stays where it is, as **Pick**, with **No commit of the list matches this fixup: left in place**. An `amend!` commit with nothing below its `amend!` line would leave an empty message: the row is flagged and the rebase cannot start until you write one.

The rest is the usual editor: change what you want, then [confirm and run](#confirm-and-run). A rebase that rewrites pushed commits needs a force push, and the rebase itself is not undoable.

## Edit the message of one commit

To change only the message of a commit, without opening the editor, right-click the commit in the graph and choose **Edit commit message…**. The **Edit the message of _abc1234_** dialog shows the full message (summary, blank line, body); edit it, then click **Change message** or press <kbd>⌘↵</kbd> / <kbd>Ctrl+↵</kbd>. The button stays disabled while the message is unchanged or its first line is empty.

You can also edit it in place from the **Commit details** panel: select the commit, then click its message, or the pencil that appears on hover (**Edit commit message**). The header turns into a **Commit summary** field with a character counter (_n_/72), a **Description (optional)** field and the same explanation as the dialog. Click **Change message** or press <kbd>⌘↵</kbd> / <kbd>Ctrl+↵</kbd>; <kbd>Esc</kbd> or **Cancel** discards the edit. Selecting text in the message to copy it does not start an edit. Once the message is changed, the graph selects the rewritten commit. The pencil is disabled while an operation is in progress; if the change fails, the edited message stays in the fields.

| Commit                                | What yaggui does                                                                                                                                                                                                                                                 | Command                                                                  |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| The last commit (HEAD)                | Amends it with the new message. Staged changes are not included, and the working copy can have changes. Undoable like an amend.                                                                                                                                  | `git commit --amend --only --allow-empty --no-verify --cleanup=verbatim` |
| An older commit of the current branch | Runs an interactive rebase from its parent: this commit is reworded, the commits after it are replayed unchanged and get new SHAs. Same rules as a rebase: no local changes to tracked files, no merge after the commit, no operation in progress. Not undoable. | `git rebase --interactive <parent>`                                      |

The message is kept as typed (lines starting with `#` included). The `pre-commit` and `commit-msg` hooks do not run, since the content does not change. If the rewritten commits were already pushed, the next push needs a force push.

The toast reads "Message changed (_abc1234_)", with the new SHA. Errors:

- "This commit is not on the current branch: check out its branch to change its message."
- "The first commit of the repository can only be reworded while it is HEAD."
- "This commit was brought in by a merge: yaggui cannot rewrite it."

## Undo

An interactive rebase is not recorded in the undo history: <kbd>⌘Z</kbd> does not revert it. While it is in progress, **Abort rebase** restores the branch. After it completes, find the previous tip in the [reflog](../../inspect/reflog/) and reset the branch to it. See [Undo and redo](../../history/undo-and-redo/).
